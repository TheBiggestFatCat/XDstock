## 1. 项目概览

一个 QQ 群风格的**模拟炒股网页游戏**：玩家做多/做空、挂限价单、打工赚钱、买主题皮肤和技能、
互相偷钱、抢指数涨跌、发表情互动（同一只票一个互动区）。

管理端在页面「管理」标签里：5 个标签页（控制台 / 市场 / 个股 / 玩家 / 参数），
控制台可以实时看真人玩家的每一单（股数/价格/金额/杠杆/方向）。

| 项 | 值 |
|---|---|
| 语言/运行时 | Node.js（ES Module，**零第三方依赖**） |
| 服务端 | `node:http` 手写路由 + SSE 推送 |
| 前端 | 原生 HTML/CSS/JS，**无构建步骤** |
| 存储 | 单个 `data/db.json`，防抖写入 |
| 时间粒度 | `tickMs = 5000`（1 轮 = 5 秒） |
| 部署 | 腾讯云 47.103.83.218，`/opt/xdstock`，systemd 服务 `xdstock` |

**设计底线**：不引入任何 npm 依赖、不引入打包器。所有功能用标准库 + 原生浏览器 API 实现。

## 5. 每轮 tick 的流水线（`src/engine.js#stepMarket`）

顺序**不能随意调整**，会影响结算正确性：

```
1. 新闻推进（阶段切换、到期清理）
2. 券商活跃度中枢 EMA、汇率 EMA
3. 每只票走一步 stepStock()
     噪声 → 新闻冲击 → 漂移 → 特质修正 → 均值回归 → 散户情绪 → 玩家冲击 → 价格钳制
4. genMarketTrades()      虚假成交（写流水 + 成交额记进 st.mflow）
   stepHotMoney()         游资：到点换板块（卖旧买新，也记进 st.mflow）
5. ~~天气抽奖~~（2026-11 已删：没有股票再用 `trait.lottery`，`lotteryFactor` 公式保留并有测试）
   - ⚠️ 幅度必须**对数对称**：涨 ×(1+p)、跌 ×1/(1+p)（`engine.js#lotteryFactor`）。
     曾经用「涨 ×(1+p) / 跌 ×(1−p)」，看着 50/50，但期望对数收益 ½ln(1−p²) 恒为负，
     按 ±12~40% 算是 **−3.5%/次**，0.0006/轮 → **−1.5%/小时**，
     结果这只票营收连涨、股价却从 45 一路跌到 9（财报没坏，是抽奖把它拖死了）
6. 汇率向目标价靠拢
7. 指数：成分股价格 → 加权 → 求 DENG 值
8. 小灯指数：同上，取市值最小 7 家 → DENGS
9. rebalanceIndex()       到点调仓（DENG 与 DENGS 同步节奏）
10. runReports()          到点发财报（兄弟股同轮发）
11. 每只票指数标的同步：db.stocks.DENG / DENGS 的 price 与 series 跟随指数
```

`processOrders()`（撮合）由 `server.js` 的 tick 定时器在 `stepMarket` 之后调用。

## 6. 核心子系统

### 6.1 股价引擎（`stepStock`）

对数收益率可加模型：

```js
logRet += 噪声(vol) + 新闻冲击 + 漂移 + 特质修正 + 均值回归 + 散户情绪 + 玩家冲击
price  = price * exp(logRet)
```

- **均值回归**：`logRet += k * ln(fair / price)`，`k = cfg.meanReversion * trait.revMult`
- **散户情绪**：每隔一段**随机周期**重掷 `v ∈ [-1,1]`（`sentRollMin`~`sentRollMax`，默认 480~960 轮，
  均值仍是 1 小时，但每只票各抽各的，不会全场同一轮换情绪）；每 `sentTicks`(12) 施加
  `v * strength * (drift + (1 - drift) * rand(-1,1))`
  - **情绪值的分布（`sentimentEdge` 默认 3，个股 `trait.sentEdge` 可覆盖）**：
    不是直接 `Math.random()*2-1`，而是取均匀 `r`、令 `t = 1-|r|` 后
    `|v| = 1 - ln(1 + k·t)/ln(1 + k)` —— **越靠 ±1 越难抽到，中间更容易**
    | k | 均值\|v\| | 中位 | P(\|v\|>0.8) | P(\|v\|>0.95) |
    |---|---|---|---|---|
    | 0（均匀） | 0.500 | 0.50 | 20.0% | 4.9% |
    | 3（默认） | 0.388 | 0.34 | 10.7% | 2.4% |
    | 9（很陡） | 0.323 | 0.26 | 6.5% | 1.3% |
    ⚠️ 调大 k 会让「平均情绪强度」降低（k=3 约 −22%），想让整体推力不变就把 `strength` 乘回去
  - **方向分量 `drift`（`sentimentDrift` 默认 0.6，个股 `trait.sentDrift` 可覆盖）**：
    `drift = 0` 是旧行为——乘的是对称的 `U(-1,1)`，`E[swing] = 0`，
    **v 只决定抖多大，不决定涨还是跌**；`drift = 1` 时 `swing ≡ v × strength`，v 直接决定涨跌。
    0.6 = 「60% 方向 + 40% 噪声」（实测 `v=+1` 跑 3000 轮累积偏移 ≈ +7.2 = 0.6×0.004×3000）
  - 「情绪读心」主题（`mind`）读的就是 `st.sentiment`；**`drift = 0` 时读出来没有方向性意义**
  - ⚠️ **读心会给假值**：每次情绪重掷时按 `mindFakeChance`（默认 0.5）决定这次显示的是不是假值，
    假值用同一套公式 `rollSentimentV(edge)` 重抽（分布完全一致，看不出来），存在
    `st.sentiment.viewV` / `viewFake` 里，**撑到下一次重掷才换**（不会每轮跳）
  - 假值**只影响面板**：价格推力永远用真的 `st.sentiment.v`（`tests/mind-view.mjs` 有断言：
    `drift=1` 时 `lastSwing ÷ strength` 必须等于真值）
  - `mindFakeChance`：0 = 永远准，0.5 = 一半假，1 = 全假；管理面板「商城」组可调
  - **强度换算（实测公式，`node tests/sim-sentiment.mjs` 可复现）**：
    - 每小时方向推力 = `720 ÷ sentTicks × strength × drift × v`
      （默认 12 轮 / 0.25% / drift 0.6 → v=1 时 9%/小时）
    - 每小时情绪噪声 σ = `strength × |v| × (1 - drift) / √3 × √(720 ÷ sentTicks)`
      （默认参数下约 1.7% vs 线上噪声 26.8%，**只占 6%**）
    - 跟均值回归拔河（k=0.0004 → 每小时拉回 25% 的 log 缺口）：
      持续 v 下的均衡偏离 ≈ `e^(推力 ÷ 0.25) − 1`，
      9%/小时 → 约 43% 溢价；21.6%/小时 → 137%（接近 `maxPremium` 2.5 的 150% 上限）
    - v 每 480~960 轮重掷一次，所以效果是 **2~4 小时一段的趋势**，不是永久漂移
  - **调参建议**：标准 0.25%（每小时 9%）、情绪派 0.4%（14%）、稳健 0.15~0.2%；
    超过 0.6% 会顶到估值上限、读心反而失去区分度
  - ⚠️ **参数优先级：个股 trait 覆盖 → 全局 config 兜底**。管理面板「散户情绪」组是**全局默认值**，
    个股面板里的同名字段是**覆盖**（留空 = 跟随全局，保存时传 `null` 删除覆盖）
  - 历史坑：`migrate` 曾经给每只票都种了一遍出厂默认值（0.004 / 12 / 480~960），
    把全局参数永久遮住，改全局完全不生效。现在 `migrate` 做一次性清理（根字段 `sentTraitMigrated` 标记），
    只删「等于出厂默认」的个股字段，单独调过的值保留
- **玩家冲击**：`impact = flow * playerImpactStrength * factor`，封顶 `playerImpactMax`；
  `factor = (impactRefFreeCap / freeCap)^0.6`，大盘股被削弱、小盘股被放大
- **市场资金冲击（2026-11）**：虚假成交 + 游资的成交额走**独立通道** `st.mflow`，
  `impact = mflow * marketImpactStrength * factor`（同一个 factor），封顶 `marketImpactMax`，
  每轮 `* marketImpactDecay` 衰减。**玩家的 `st.flow` 完全没动**，两套上限互不抢占
  （游资砸 3000 万不会把玩家那 12 单位的上限占掉）

  **两条通道的力度其实不一样**（管理面板已合并成「交易规则 → 市场冲击（玩家 vs 虚假成交 / 游资）」一组）：

  | | 玩家 `st.flow` | 虚假成交 / 游资 `st.mflow` |
  |---|---|---|
  | 压力基准 `ref` | `playerImpactRef` = **100 万** | `marketImpactRef` = **1000 万** |
  | 每单位推动 | `playerImpactStrength` = **0.0009** | `marketImpactStrength` = **0.002** |
  | 单轮封顶 | `playerImpactMax` = 0.008 | `marketImpactMax` = 0.008 |
  | 衰减 | `playerImpactDecay` = 0.88 | `marketImpactDecay` = 0.85 |
  | 额外项 | `playerImpactTail`（成交当轮全额外，后续按倍率打折） | 无 |
  | 压力上限 | 12 单位 = 1200 万 | 8 单位 = 8000 万 |

  实测（默认值、不考虑 `impactFactor`）：

  | 成交额 | 玩家首轮 / 累计 | 市场首轮 / 累计 |
  |---|---|---|
  | 100 万 | 0.090% / 0.74% | 0.020% / 0.11% |
  | 1000 万 | 0.800%（封顶）/ 7.6% | 0.200% / 1.32% |
  | 3000 万 | 0.800%（封顶）/ 8.8% | 0.600% / 4.05% |

  → **同样的钱，玩家通道比市场通道重约 4.5 倍（首轮）**；系数填成一样的数**不等于**效果一样
  （同样 1000 万、同样 0.002/0.85：玩家通道累计 10.3%，市场通道 1.3%，差 7.8 倍 —— 差在基准金额）。
  想让两边等力：把 `marketImpactRef` 调到 1000000、`marketImpactStrength` 调到 0.0009、
  `marketImpactDecay` 调到 0.88，三个都对齐后两边才真正同效（封顶本来就一样）
- **钳制**：单轮涨跌幅限制、ST 阈值触发出局

### 6.2 财报与估值（`src/fundamentals.js`）

- 每 `reportIntervalTicks`(720) 发一期
- **价值线（fair）用最近 `fairLookback` 期的 EPS 趋势拟合（2026-11 改）**：
  - 把最近 N 期（默认 8，管理面板「个股 → 财报节奏与噪声 → 价值线拟合期数」可改，3~12）
    EPS 取对数做一元线性回归，取**拟合线在最后一期的值**当"当前盈利水平"
  - `fair = max(拟合EPS × 行业PE × (1+成长溢价), BPS × 0.8)`，成长溢价用**拟合斜率**（不是最后一期的 growth），
    再走 70/30 平滑。有效样本 < 3 期 → 回退到 `fairFromReport`（只看最后一期）
  - 为什么改：以前只看最后一期 EPS，一期财报抽到 ±6% 噪声，整条价值线就被拽走 6%。
    N=8 时端点权重 42%，单期噪声传递约一半，且**不像几何平均那样滞后趋势**
    （5 期窗口端点权重 60%、传递 90%，基本等于没改）
  - 净资产底线（`BPS × 0.8`）不受影响：一半的票价值线本来就是它撑着的，拟合改不动它们
- 测试：`node tests/fair-history.mjs`（31 条）
- **财报基线（2026-11 改版）：零期望随机偏移，体量越大偏移越小**
  ```
  sizeCap  = 市值（fair × 总股本）
  σ        = clamp(reportVol × √(reportRefCap / sizeCap), reportVolMin, reportVolMax)
  logShift = clamp(gauss() × σ, −0.35, 0.35)      // 对数空间零均值
  growth   = exp(logShift) − 1
  ```
  - 默认 `reportVol 0.05` / `reportRefCap 1000 亿` / 下限 `0.01` / 上限 `0.1`
    → 1000 亿的公司每期 ±5%，4000 亿 ±2.5%，小盘票顶到上限 ±10%
  - **对数空间取零均值**：直接乘随机数会有 Itô 漂移，玩家会看到「所有公司都在慢慢缩水」
  - **不再有**「天生体质 `TRAIT_BIAS`」「向行业中枢回归」「12% 景气周期」「规模衰减 `decay`」这几套
    —— 上一期营收 + 随机偏移就是这一期，没有方向偏好
  - 纯随机路径**不乘**天花板剩余空间（乘了等于正偏移永远被削，期望就成了慢慢缩水）；
    失控由 `revCeil` 硬夹负责。地板/天花板（`0.25×` / `×growthCeiling`）仍然有效
- **市场预期 `expectedGrowth` = 最近 5 期财报的走势拟合（2026-11 改）**
  - 实现：`fundamentals.js#expectedGrowthFromHistory(history, 5)`
    —— 把最后 5 期的**营收**取对数做一元线性回归，拟合线往下一格涨多少就是预期同比
    （对数空间做，所以「+10% 再 +10%」这种等比走势是直线）
  - **有效样本 < 3 期**（新上市 / 老存档还没攒够历史）才回退到模型口径：
    - 纯随机票 → 0；`gold` → 目标增速 + 金价那段；`capTarget` / `steady` / `weather` → 各自的理论值
  - 极端走势夹在 `[-35%, +90%]`（和 `growth` 的夹法一致），不会把预期吹到天上
  - 「超预期 / 不及预期」现在是**相对市场共识**说的：实际 − 走势外推，
    `> +2pp` 超预期 / `< −2pp` 不及预期，发报冲击 `clamp(surprise × 0.8, ±6%)` 打在价格上
  - 财报面板新增一行「市场预期 +x.xx% / 判定 / 差 x.xxpp（按最近 5 期财报走势拟合）」，
    所以 `report.expectedGrowth` 现在**会下发**（它是往期公开营收的函数，不算内部参数；
    `src/wire.js#REPORT_KEYS` 已加）
  - 「金融大鳄」的 `pendingReport` 也是同一套：预览里的 `expected`/`surprise`/`verdict`
    和发报时完全一致（提前 20 轮生成，期间历史不变）
  - 测试：`node tests/report-trend-expectation.mjs`（25 条）
- **特质驱动**的票仍然走各自的确定性路径（`growth` 的算法不变，只是「预期」改成看走势）：
  - `steady`（麦当劳）：`g0 × √(离市值天花板还剩多少)`
  - `capTarget`（弦卷 / 矿工银行 / 肯德基）：由目标市值反推营收，每期收掉 rate 的差距
  - `gold`（矿工银行）：目标增速 + 金价涨跌 × 系数 ± 随机浮动
  - `weather`：`score × swing × decay`（天气股已于 2026-11 下市，代码保留）
- **券商 / 外汇的成交活跃度是「相对口径」（2026-11 修）**：
  `engine.js#volumeFactorOf(db)` = `volumeAvg / volumeRef`，1 表示「和最近这几个小时一样活跃」。
  - `volumeAvg` 是成交笔数的快 EMA（α=0.02，约 50 轮），`volumeRef` 是它的慢 EMA（α=0.0005，约 2 小时）
  - ⚠️ **历史坑**：以前写死「成交笔数 ÷ 2」（2 笔/轮算正常），那是绝对口径 —— 玩家少、成交冷清时
    永远远小于 0.2，券商营收被 25% 地板夹死，**每期财报都是「同比 0.00%」**，
    金融大鳄的提前预览也就永远显示「符合预期 +0.00pp」，技能等于没有（2026-11 线上就是这状态）。
    相对口径下平时就在 1 附近，只有「明显比平常热闹 / 冷清」才偏，和玩家总数无关
  - 一笔成交都没有时 `volumeFactorOf` 直接返回 1（和以前 `Number(x)||1` 的老口径一致），
    不会把券商按到地板上
  - `migrate` 自愈：券商 / 外汇的营收如果贴着 `baseRevenue` 的 25% 地板，
    把基准营收重置为现值（否则每期都是 0%，而且再也不会浮动）。只在病态状态触发，正常存档不动
  - 测试：`node tests/tycoon-broker.mjs`（26 条）
- 联动：汇率（留美外汇）、券商成交活跃度（小灯证券）；天气股（戴夫种业 / 哈基蜂业）已于 2026-11 下市
- **天气（农业股）**：`db.weather = { score, label, rollTick }`，`score ∈ [-1,1]`
  - **每期财报重掷一次**（`fundamentals.js#rollWeather`：上期分数 ×0.5 + 高斯噪声，带均值回归），
    同一轮只掷一次、兄弟股共用；`rollTick` 用来保证「一轮只掷一次」
  - 天气决定增速：`growth = score × swing × decay`（**仍要乘规模衰减**，别写成纯 `score×swing`）
  - 「市场预期」现在**不再取模型里加噪声之前的那个值**，而是按最近 5 期营收走势拟合
    （见上文「市场预期 = 最近 5 期财报的走势拟合」）；天气变了 → 走势变了 → 预期跟着变
  - `weatherTarget = fair × (1 + score × swing)`，`engine.js` 每轮按 `trait.anticipate`
    让 `fair` 往它靠；`anticipate` 别超过 0.001，否则两次财报之间 fair 会被拖低 20%+
  - ⚠️ 历史坑：`db.weather` 曾经只在缺失时生成一次、之后永不重掷，
    导致一次抽到「灾害歉收」就让天气股永远负增长（2026-11 修复，
    老存档由 `migrate` 解冻：先归零成「平平无奇」，之后每期正常重掷）
  - **天气只留给引擎和财报用，不下发前端**（`marketPayload` 里没有 `weather` 字段），
    玩家只能从财报里的「同比」间接感受，前端不要再加天气徽章/提示
- **金融大鳄预览（2026-11 重做）**：
  - **只有金融板块**（券商 / 外汇）在发报前 `TYCOON_LEAD_TICKS`(20) 轮把下一期算好写进
    `st.pendingReport`；判定统一用 `fundamentals.js#isTycoonSector(st)`，
    引擎 / `api.js` / `server.js` **三处必须用同一个函数**，否则会出现「有倒计时但永远没预览」
  - 发布时直接用 `pendingReport`，所以「看到什么就发什么」，数字不会再变
  - payload（两处共用 `fundamentals.js#tycoonPreviewPayload`，别再各写一份）：
    `stocks[code].preview = { revenue, netProfit, eps, growth, expected, surprise,
    verdict, shockPct, tickLeft, previewIn, expectPct }`，只有 `player.skill === 'tycoon'` 才下发
  - **`stocks[code].previewIn`**：距离「可以预览」还有多少轮（`nextReportTick − tick − 20`），
    **只有金融板块下发，其余票是 `null`**。`> 0` 前端显示「🐊 还需 N 轮可预览」，
    `<= 0` 是窗口内，`null` 表示这只票没有预览（前端**必须先把 null 挡掉**：
    `Number(null) === 0` 会被误判成「已在窗口内」）
  - 股票列表每行也带 🐊 角标（`updateTycoonChips()`）：窗口内显示「预览」，窗口外显示剩余轮数
  - ⚠️ `server.js#tickPayload` 的两处判断曾经写成 `player.theme`，皮肤和技能拆开后必须读
    `player.skill || player.theme`，否则「只换外观没换技能」的人也能看到预览
  - `verdict` 与发报时 `runReports` 的口径完全一致：
    `surprise = clamp(growth − expected, ±30%)`，`> +2pp` = `beat` / `< −2pp` = `miss` / 其余 `inline`；
    `shockPct = clamp(surprise × 0.8, ±6%) × 100`（就是发报那一刻会打在价格上的幅度）
  - ⚠️ 生成 `pendingReport` 的 ctx **必须带 `weather`**（`st.weather?.score`）：
    少了它天气股增速恒为 0，而且因为发布时不再重算，等于永久冻结
  - 前端：`app.js#renderTycoonPreview()` + `.tp-*` 样式，三色卡片（超预期红 / 不及预期绿 / 符合灰）
  - 测试：`node tests/tycoon-preview.mjs`（51 条）+ `node tests/tycoon-broker.mjs`（26 条）
- **净资产（BPS）**：`bps = nextBps(上期, eps, { pe, growth, retain })`
  - 只把 `retain ∈ [0.15, 0.3]` 的利润并进账面（其余视作分红/回购，发给场外股东）
  - **账面封顶**：`0.8×BPS` 超过「盈利估值 × 2」时不允许再涨；已经超顶的每期向顶收敛 0.3%
    （`BOOK_SHRINK`，半衰期约 230 期）
  - ⚠️ 历史坑：以前是 `eps × rand(0.4, 0.9)` 全额留存且没有封顶，于是账面越垫越高，
    业务在萎缩的公司（XD 的 EPS 才 1 块、BPS 有 150 块）反而"越萎缩越值钱"，
    fair 一路涨到盈利估值的 10 倍以上（2026-11 修复）

#### 个股市值天花板 / 市值目标（`st.capCeiling` / `st.capTarget`）

两种「给一只票定终局」的机制，都写在 `src/stocks.js` 的种子里，**由代码管，不进管理面板**：

| 字段 | 含义 | 谁在用 | 实现位置 |
|---|---|---|---|
| `capCeiling` | 市值**上限**，只允许无限靠近 | **目前没有票在用**（麦当劳 2026-11 已按需求去掉） | `runReports` 里 `fair` 夹到 `capCeiling/shares × 0.95`；`stepStock` 再硬夹价格 |
| `capTarget` + `capTargetRate` | 市值**目标**，按速率收敛过去（可上可下） | 弦卷财团 XJ（5000 亿）、矿工银行 MB（3000 亿）、肯德基 KFC（1000 亿） | 营收 / 净资产 / `fair` 三处同时朝它走 |

> **2026-11：麦当劳去掉 `capCeiling`**。原来 `capCeiling = 1e12`（1 万亿）会把价格硬夹在
> `1e12 / 6 亿股 = 1666.67`，涨到那里就再也上不去（15m K 线最高价正好卡在 1666.6667），
> 看起来像「股价卡死」。现在 MCD 只剩两条**全局**规则：
> 价格 ≤ `fair × maxPremium`（防泡沫，所有票都吃）、营收 ≤ `baseRev × growthCeiling`（4.5 倍）。
> 引擎仍然支持 `capCeiling`（`tests/mcd.mjs` 第 6 段用手动设的值验证），以后想给某只票设就照写。

`capTarget` 的三条腿（缺一条就到不了终点）：

1. **营收**：由目标市值反推「配得上它的营收」`tgtRev`，`growth = (tgtRev / 上期营收 − 1) × rate`
2. **净资产**：`bps` 每期朝 `目标价 / 0.8 × 0.95` 靠 `rate`，并把 `retain` 压到 0.02
   （不压的话 `BPS × 0.8` 那条地板会把 `fair` 拖住，市值永远掉不下去）
3. **合理价**：`runReports` 里 `fair += (目标价 − fair) × rate`，并且**目标上方只许跌不许涨**

`rate` 是「每期走完剩余差距的百分比」，1 期 = 1 小时：`0.06` 时走完一半约 11 小时，
走完 99% 约 61 小时。财报也按 `steady` 那套平滑（增速 ±0.25%、净利率不抖），
否则 EPS 随机跳动会让 PE 看着像过山车。

- ⚠️ **老存档不会自动带上这两个字段**：`migrate` 里必须按种子同步
  （`st.capCeiling / capTarget / capTargetRate / growthCeiling / rallyHours`），
  否则新加的目标只对「新档」生效，线上等于没做
- 测试：`node tests/xj-target.mjs`（17 条，覆盖收敛速度、目标上方不反弹、PE 不失真、老档迁移）

| 症状 | 根因 | 修法 |
|---|---|---|
| 营收已经跌到地板，财报却报「−35% 暴跌」 | 报的是 `expectedGrowth`（夹之前的值） | `growth` 改成**营收真实变化**，被夹时 `expectedGrowth` 同步 |

### 6.2.1 分红派息（含除权）

- **发放时点**：每只股票发报的那一轮（`runReports` 里），各票错开、每 720 轮一次
  → 单只票每小时派一次，全市场平均每 6~9 分钟有一笔
- **金额**：`dividendPerShare(st, { rate, cap })` = `max(0, EPS) × 行业派息率 × 倍率`，
  再按 `现价 × cap` 截断。**因为封顶跟着现价走，所以这个数每轮都在变**，
  前端 `st.dps` 每轮从 `tickPayload` 刷新，财报面板显示的就是它
- **行业派息率**（`INDUSTRY[行业].payout`，参考现实：成长股少分、金融多分）

  | 行业 | 派息率 | 现实参照 | 目标年化股息率 |
  |---|---|---|---|
  | 金融 | 40% | A 股银行 30~40% | ~4.2% |
  | 消费 | 45% | 沪深 300 35~45% | ~2.6% |
  | 传媒 | 30% | 2~3% | ~2.0% |
  | 外汇 | 35% | 金融同业 | ~3.0% |
  | 科技 | 12% | 成长股 0~20% | ~0.5% |

  → **股息率 = 派息率 ÷ 市盈率**，跟现实一致：低 PE 的票股息率高（LMFX PE≈9 → 6%/年），
  被炒贵的票股息率低（XD PE 100+ → 不到 1%/年）。改派息率会影响这个分布。
- **配置**（管理面板「分红派息」组）：
  - `dividendRate` **派息倍率**（默认 1 = 按行业标准，0 = 停发，2 = 全部翻倍）
  - `dividendCap` 单期股息率封顶（默认 0.015 = 1.5%/期 ≈ 6%/年，0 = 不限）
- **谁收钱**：持有该股多头、且**持满一期**（`openedTick ≤ 本轮发报 tick − interval`）的玩家，
  `现金 += qty × dps`；空头**补息**（`现金 -= qty × dps`，扣到 0 为止，不追缴）
  - 「持满一期」是防刷：否则财报前买入、发完立刻卖就能白拿
  - 亏损公司（EPS ≤ 0）不分红
- **除权（除息）**：派完立刻 `st.price -= dps`（保底 0.01），不管有没有人持有
  - 多头：现金 +qty×dps、持仓市值 −qty×dps → **总资产不变**（跟现实一致）
  - 空头：补息 −qty×dps、持仓因跌价 +qty×dps → 也是净 0，公平
  - 除权后价格低于 fair，均值回归会把它慢慢拉回来 = 现实里的**填权**
  - ⚠️ **没有除权 = 直接印钱**：按 0.5%/期算，满仓持有的人每小时白拿 0.5%、一天 12%，
    2026-11 上线分红时漏了这一步，发现后立刻停发并补上
  - 顺序：**先用除权前价格算 dps → 派息 → 再除权**（反过来会算小）
- **事件下发**：`db.dividendEvents`（每轮重置）→ `server.js` 按人塞进 `payload.dividends`
  →  前端 `handleDividends()` 弹 toast；累计值走 `player.dividendEarned`，
  在 `marketPayload.me` 里下发，显示在「我的 → 累计股息」
- **同时写进交易记录**：派息也 `logTrade({ action: 'dividend', side, qty, price: dps, amount, pnl, reason: 'dividend' })`，
  这样「我的 → 交易记录」里能看到每一笔股息（否则只有一条一闪而过的 toast，离线时完全看不到）
  - 前端 `REASON_LABEL.dividend` = 「派息」；动作列显示「股息 / 补股息」，
    成交价 / 杠杆 / 手续费留「—」，金额和盈亏列显示带符号的金额（每股金额放在 `title` 里）
  - 加这条不影响别处：`/api/stock-trades` 只取 `action === 'open' | 'close'`，
    `db.tradesThisTick`（券商营收）也不会把派息算成成交
- **语义迁移**：`dividendRate` 以前是「绝对派息率」（0.35），现在是「倍率」；
  `store.js#migrate` 用 `dividendMigrated` 一次性重置成 1 + 封顶 0.015

#### 6.2.0 价值线拟合口径的选型实验（2026-11）

用线上存档副本跑的三组对比（`fairLookback` 决定窗口，公式不变）：

| 口径 | 单期财报 ±5% 传到价值线 | 连续 +5%/期 的趋势滞后 | 与旧口径的偏离 |
|---|---|---|---|
| 旧：只看最后一期 | **5.00%** | 0 | — |
| 5 期回归@末端 | 4.48% | 0 | 下一期 ≤7.7% / 30 期 ≤9.7% |
| **8 期回归@末端（当前默认）** | **2.1~2.7%** | **0** | 下一期 ≤7.7% / 30 期 ≤9.4% |
| 5 期几何平均 + 趋势溢价 | 2.46% | −9.3% | ≤8.4% |
| 5 期几何平均 / 截尾均值 | 0~1.0% | −15.6% | ≤8.6% |

- 端点杠杆 = `1/n + (x−x̄)²/Sxx`：n=5 时最后一期占 60%，n=8 降到 42%
  → **想降噪就加长窗口**，5 期基本等于没改；几何平均/截尾均值最稳，但对稳态成长股会低估约 15%
- 线上 10 只票里 **5 只（TGW / MAMA / DFY / NW / XD）的价值线是 `BPS × 0.8` 撑着的**，
  拟合怎么改都不动它们；受影响的是盈利撑着的 LU / MB / XJ / MCD / KFC
- 换口径后 `tests/kfc-stock.mjs` 的「第 20 期市值」会小幅下移，阈值已放宽到 870（随机序列，没有种子）

### 6.3 指数

| | DENG（灯证指数） | DENGS（小灯指数） |
|---|---|---|
| 成分 | 全部 10 只非指数股 | 市值最小 7 只 |

**成分股停牌 ≠ 退出指数（2026-11 修的闪崩）**

- 指数只遍历 `status !== 'delisted'` 的成分股，**停牌的照算**，用它最后成交的 `price`

- ⚠️ 历史 bug：以前遍历的是 `status === 'normal'`，麦当劳一停牌，它那 22.9% 的权重

- 退市剔除靠 `stale` 判定（权重表里的票已经不在成分里）→ 立刻调仓；
  调仓时 `scale = 当前点位`，所以剔除/纳入都**不跳空**
- DENGS（小灯指数）同样规则：停牌不踢出篮子；只有「掉出最小 7 家」才调仓（`sStale` 判定）
- 测试：`node tests/index-suspension.mjs`（23 条：停牌不闪崩、停 50 轮不掉、复牌当轮恢复、
  退市不跳空、DENGS 同规则、调仓仍正常）

### 6.4 交易与挂单（`trading.js` / `orders.js`）

- 只支持**限价单**，无市价单（止盈止损转来的 auto 单例外，见 6.5）
- **不再有「每轮每只票只成交一张」**——那个规则会被 1 股小单占位卡死全服
- 撮合顺序：**风控单（auto）→ 价格优先 → 时间优先**
- 成交金额上限按**【玩家 × 标的 × 方向】**计：
  ```
  fillCap = maxFillNotionalPerTick
          + 通道等级 × (shopChannelStep × 账号等级)   ← 通道每级增量按等级放大
          + 账号等级 × levelFillBonus                 （每级 +100 万，人人都有）
  ```
  通道那条：**每买 1 级的增量 = `shopChannelStep` × 玩家等级**
  （Lv.1 买 1 级 +10 万，Lv.3 买 1 级 +30 万；买过通道的人升级后这份也会同步变大）。
  因为是每次现算，**升级 / 加购都下一轮直接生效**，不需要迁移数据。
  展示用的单级增量走 `orders.js#channelStepFor(db, player)`，别在前端自己乘。
  同一玩家在同一只票同一方向的全部挂单共享这份预算，大单自动拆成多轮。
  统一入口是 `orders.js#fillCapFor(db, player)`，**不要在别处自己拼公式**
- 下单当轮不成交（`db.tick <= order.createdTick` 直接 skip）
- 每人每轮操作次数上限 `maxOrdersPerTick`：**在 `api.js` 的 `/api/order/limit` 里用
  `orderLimitBlocked()` 拦 + 成功后 `consumeOrderSlot()` 记一次**（以前只定义没调用，等于没有）
- 每人同时挂单上限 `maxPendingOrders`（**只数手动单**，止盈止损单不占名额）
- **杠杆滑条的颜色跟着档位走（2026-11）**：`app.js#leverageColor()` 把「当前倍率在
  `minLeverage`~`maxLeverage` 里的位置」映射成 HSL 色相 140°→0°（绿→黄→红），
  `#levLabel` 的文字色、滑块描边 `--lev-color`、滑条本身的绿→红渐变都跟着刷
  （`paintLeverageLabel()`，在 `updateCostPreview()` 里调用；改后台杠杆上下限会自动跟着变）
- 押金 = 保证金 + 手续费 + 印花税（做空）+ **冲击成本**，按最坏成交价冻结；
  成交时按比例解冻，多退少补。`estimateReserve()` 漏掉冲击成本会导致「全仓挂单成交时
  被自己卡死 → 自动撤单」
- 开空/卖单的成交价没有上限：价格上冲导致押金不够时，**按买得起的数量部分成交**，不整单撤销
- 休市时 `/api/order/limit` 返回 **423**（以前只灰按钮，接口不拦）

**限价单的语义（当前标准，别再改）**

- **成交价永远是市价 `px`，不是挂单价**。`hit = 买 ? px <= limit : px >= limit`。
  所以「现价 100 挂 300 买入」会在下一轮**按 100 成交** —— 这就是限价单「我愿意出到 300」的
  标准语义，**不是 bug**（2026-11 两次想改成「到价才买」/「拒绝高价」，都因为影响正常开仓
  被回退，用户确认现在这样是对的）
- 没有挂价上限，任何价位都能挂；也没有「到价单 / 止损单」这种类型
- **同一只票不许同时挂「开仓」和「平仓」**（`orders.js#pendingConflict`）：
  - 要开仓：这只票不能有未成交的**手动**平仓单（止盈止损的 auto 单不挡加仓）
  - 要平仓：不能有未成交的开仓单，也不能已经有平仓单在排队（auto 单也算，避免重复卖）
  - 原因：两笔一起排队时，谁先成交都会把另一笔的前提打乱 ——
    开仓先成交 → 后面那笔「平 100 股」只平掉一半；平仓先成交 → 开仓单变成满仓
  - `body.system`（自动定投等系统单）跳过这个检查；测试 `node tests/order-conflict.mjs`
- **挂单有效期**默认 `orderTtlTicks = 2000` 轮（≈ 2.8 小时），auto 单 4000 轮。
  改这个值要三处同步：`config.js` 默认值、`api.js` 的 `?? 2000`、
  `orders.js` / `trading.js` 里的 `num(cfg.orderTtlTicks, 2000)` 兜底，
  否则老存档（已有该字段）和缺字段的新档会拿到不同的有效期

**下单方式：传统挂单 / 简单模式（2026-11 新增）**

前端下单卡片多了一个「下单方式」切换（`#orderStyleSwitch`，`.os-btn[data-style="limit"|"simple"]`），
**默认传统挂单**（行为和以前一模一样），选择记在 `localStorage.xd_order_style`。

| | 传统挂单（默认） | 简单模式（市价单） |
|---|---|---|
| 提交参数 | `{ limit }` | `{ simple: true }`（`limit` 可省，只用于显示 / 估押金 / 排序） |
| 成交条件 | 价格到线才成交（`hit`） | **不看 limit**，下一轮无条件按市价成交 |
| 成交价 | 市价 `px` | 市价 `px`（本来就一样） |
| 押金 | 买单按限价、卖单按 `max(限价, 现价)` | **按现价** `× 1.03`（跳空缓冲，不看 limit） |
| 排队优先级 | 风控单之后，按价格优先 → 时间优先 | 风控单之后、**限价单之前** |
| 流水 `reason` | `limit` | `market`（「我的 · 交易记录」显示「市价」） |

- 两条分支只在 `orders.js#processOrders` 的那个 `if` 上分叉，**其余全部共用**：押金冻结 / 退回、
  每轮成交额度（大单照样分几轮吃完）、同时挂单上限、同票开平冲突、撤单、TTL、停牌与退市处理
- `pendingConflict()`、`fillCapFor()`、`orderLimitBlocked()` 都不区分模式，
  所以**两种模式互不影响**：不发 `simple` 就是原来的行为，一行都没变
- 「允许限价挂单」`limitOrderEnabled = 0` **只关限价单**，简单模式照常可用（它是市价单，不是挂单）
- 押金多冻 3%（`orders.js#SIMPLE_RESERVE_SLIP`）：下一轮价格会变，按现价冻会在跳空那一刻报
  「现金不足」；真跳穿 3% 也不会崩，撮合按「买得起的数量」部分成交（和限价单同一套兜底）
- **「全仓」必须按押金口径算**（`app.js#maxAffordableQty`）：简单模式下每股成本乘 `1.03`、
  预算留 1%（`cash × 0.99`，兜住「下单那一刻价格又跳了」）。按现价算会必然差 3%，
  点全仓直接报「押金不足」（2026-11 修过的 bug）。成本预估里「所需资金」也显示这个冻结额，
  否则会出现「所需 $X ≤ 现金 $X，却提示资金不足」的矛盾；切模式时若原数量超上限会自动收敛
- **`simple` 字段要同时加到两处 payload**：`api.js#publicPlayer` 与 `server.js#tickPayload` 的
  `orders[]` 映射（前端「我的挂单」靠它显示「市价」而不是挂单价）
- 前端：`app.js#applyOrderStyle()` 管按钮选中态 + 挂单价字段显隐（class 与 `style.display` 双保险）；
  `placeLimit()` 用 `isSimpleOrder()` 决定是否带 `simple`；按钮文案与橙色配色在 `updateOrderBtnLabel()`
- 移动端：`.os-btn` 基础 `min-height:46px`，`@media (max-width:760px)` 提到 54px（触控目标），
  这条媒体查询**必须放在 styles.css 最后**——放中间会被后面的基础样式覆盖掉（踩过）
- 测试：`node tests/order-simple.mjs`（46 条：不看限价、按下一轮市价成交、押金缓冲、分批成交、
  平仓 reason、撤单退款、停牌、两种模式互不干扰）

**前端让利**：`public/app.js` 的 `getSlipPct()` 读 `localStorage.xd_slip`（默认 0.5%），
决定自动挂单价比现价让多少。**必须每次现读**，不能存成模块级常量；`#slipInput`
要绑 `input/change` 事件，否则输入框是死的（这两个坑都踩过）。

### 6.5 止盈止损

- 每个持仓可有**多条**分段条件单：`pos.tpsl = [{ id, kind: 'tp'|'sl', price, qty }]`
- 每条可独立设数量（部分平仓）
- 触发后标记 `fired`，不再重复触发
- 触发时**不直接成交**，而是生成一张 `auto` 平仓单，交给下一轮撮合
- ⚠️ **auto 单必须当轮强制成交**（`orders.js` 里对 `order.auto` 跳过限价判断）。
  如果还按限价成交流程走，价格跳空到限价下方时卖单会永远等不到成交——止损形同虚设
- 手动挂的远价平仓单**不算**「已经在平仓」，不会屏蔽止损（只有 `o.auto` 才算）
- auto 单的 TTL 是 `orderTtlTicks × 2`，`expireTick` 按同一口径写入
- `pos.closing` 只用来给前端显示「止盈中/止损中」
- 每轮顺序：`stepMarket` → `processOrders`（成交）→ `checkPositions`（触发新条件）。
  所以条件触发那一轮**不会**成交，下一轮才平（`createdTick` 那一轮跳过）
- ⚠️ **2026-11 修的真 bug：撤掉 auto 单必须把条件重新武装**。
  auto 单可能因为「超时 / 手动撤单 / 连续成交失败 / 持仓没了」被 `cancelOrder` 撤掉，
  而它触发时已经把 `tpsl` 条目标成 `fired: true` —— 只要不重新武装，这条止盈止损就**永久失效**。
  现在建单时把 `tpslIds` / `tpslOrigQty` 记在单子上，`cancelOrder` 里恢复 `fired: false`，
  并按「已成交数量」扣掉预设的 `qty`（部分成交后撤单不会多平）。测试 `tests/tpsl.mjs` 第 10 段
- 自动单也吃「每轮成交上限」，大仓位会分好几轮平完（每次部分成交都会推一条带「还剩 N 股在平」的通知）；
  这期间价格继续走，属正常现象
- ⚠️ **2026-11 修的第二个 bug：止盈止损触发时必须撤掉这只票还没成交完的开仓单**。
  线上的大额开仓单是按「每轮成交上限」分批成交的，如果它还在排队，而止损已经按触发那一刻的数量平了仓，
  剩下的开仓单会继续把仓位加上去 —— 结果是「止损成交了、仓位反而更大、而且再没有止损保护」。
  现在 `checkPositions` 建自动单的同时把这些开仓单撤掉并退押金（事件里标 `canceledOpen`）。
  测试 `tests/tpsl.mjs` 第 14 段

**暗中调查**、**情绪读心**、**夜行者**是 **Lv.2 主题**（`THEME_NEED_LEVEL = { probe: 2, mind: 2, night: 2 }`，

**夜行者的时间窗**（`src/theme.js`，按**服务器本地时间** Asia/Shanghai 算）：

- `nightStartHour`（默认 20）/ `nightEndHour`（默认 4），支持跨零点；
  **`start === end` 视为不生效**（`nightEndHour: 24` 会被归一成 0，想要全天请写 `0 / 23`）
- `nightStealCooldown`（默认 50）：夜里用这个值，其余时间还是 `stealCooldownTicks`（默认 60）
- 进化后（Ⅱ 阶）用 `nightStealCooldownEvolved`（默认 20）
- 2026-11 改版：时间窗从 20:00~04:00 收紧到 **22:00~05:00**，夜里冷却从 3 轮放宽到 **50 轮**、进化后 **20 轮**
  （原来的 3 轮 = 15 秒就能再偷一次，等于无限偷；现在夜里是白天的 1.2 倍频率，进化后 3 倍）
- 判定在**服务端**：`/api/steal` 只查 `stealReadyAt`，真正写冷却的是 `server.js` 偷钱结算
  （`p.stealReadyAt = tick + stealCooldownFor(d, p)`），所以「03:59 派小偷、04:00 结算」按结算那一刻算
- 前端拿 `me.night = { active, hour, start, end, bonus, stealCd, msLeft }` 显示
  「现在是不是夜里 / 还有多久天亮」，商城卡片上也有这行提示
- 配色在 `styles.css` 的 `body[data-theme="night"]`：**颜色不受时间限制**，只有技能受限
排行榜数据本身**不公开任何持仓**（`/api/leaderboard` 里 `positions: []`），所以调查技能才有意义。
冷却存在 `player.investigateReadyAt`（绝对轮次），**空手而归不消耗冷却**。

**情绪读心**单独定价（`mindThemePrice`，默认 500 万），其余主题走 `shopThemePrice`。
它的数据跟「金融大鳄」一样是**按人下发**的：公共 payload 不带 `sent`，
`server.js` 广播时对 `skill === 'mind'` 的客户端单独合并 `stocks[].sent`，
`marketPayload` 里同理（只在 `me.skill === 'mind'` 时给）。
**下发内容只有 `{v}` 一个数**（`src/wire.js#sentWire`）：真假标记、剩余轮数、
施加间隔、方向分量都留在服务端 —— 否则 F12 一看就知道「这次读心准不准」。
读心的价值取决于情绪的方向分量 `sentimentDrift`——**如果 drift = 0，v 只决定波动大小，
读出来也没有方向性意义**。

### 6.7 账号等级与商城

- `player.level` 默认 1
- 升级门槛：`levelBaseAsset * levelGrowth^(level-1)`（默认 1000万 ×2 → 1000万/2000万/4000万…）
- 升级费用：**当前总资产 × `levelUpRatio`（60%）**，按点击那一刻重算；
  **这笔钱会存进丰川银行**（见 6.11），不再直接消失
- **每个等级额外提供 `levelFillBonus`（默认 100 万）的「每轮单笔成交上限」**，
  和商城「交易专属通道」叠加
- **交易专属通道的每级增量 = `shopChannelStep` × 账号等级**（2026-11 改）：
  Lv.1 每级 +10 万、Lv.3 每级 +30 万，等级越高通道越值钱。
  `shopChannelStep` 在管理面板「商城」分组里可调（调成 0 等于关掉通道加成）
- `publicPlayer` / `tickPayload` 都下发 `me.fillCap`，
  前端显示的额度一律读它，别自己按 `maxFillNotionalPerTick` 算

#### 商城：三个分页 + 等级门槛（2026-11 改版）

商城按**品类**分三个分页（不是按等级分档）：

| 分页 | `data-shop-panel` | 商品 |
|---|---|---|
| 🎨 主题 | `theme` | 金融大鳄 / 隐世仙人 / 红红的牛 / 绿绿的熊 / 暗黑大手 / 经典配色 / 暗中调查 / 情绪读心 / 夜行者 |
| 🧰 道具 | `item` | 假新闻 / 保镖 / 咸鱼代下单 / 交易专属通道 / 自定义背景 / 改名卡 / 自动定投 / 游资情报 |
| 🏅 其他 | `other` | 账号等级 / 敬请期待（Lv.3） |

### 6.8 虚假成交与游资（`marketTrades.js` / `hotmoney.js`）

成交记录里那些带小动物头像、没有真人的单子。**2026-11 起不再只是装饰：它们会真的推动股价。**

两条来源共用一套「散户身份」（`marketIdentity()`：24 个昵称 + 20 个小动物表情），
成交记录长得**完全一样**，玩家分不出哪笔是虚假成交、哪笔是游资：

| | 虚假成交 | 游资 |
|---|---|---|
| 频率 | 每轮 `rand(1,2) × marketTradesRate` 笔（默认 6 → 每轮 6~12 笔，2026-11 从 3 翻倍） | 每 20~300 轮换一次板块（每次 1 买 1 卖） |
| 金额 | 三档：1 万~10 万 / 10 万~100 万 / 100 万~1000 万，**越低档越常见**（70% / 24% / 6%） | 每笔 1000 万~3000 万 |
| 方向 | 跟着**最近 12 轮（1 分钟）**的涨跌：涨了偏买（`marketTradesChase`）、跌了偏卖（`marketTradesPanic`），一档多大幅度由 `marketTradesTrigger`（默认 3%）决定 | 换板块 = 卖掉旧的、买入新板块的一只 |
| 价格影响 | 成交额 →`st.mflow` → 逐轮释放 | 同上 |

- **追涨 / 杀跌（2026-11 改成 1 分钟动量 + 三段式限幅）**：
  方向概率在 `marketTrades.js#marketBuyProb(chg, cfg, pressure)` 里算，`chg` 由
  `marketWindowChange(st.series, marketTradesWindow)` 给出（默认 12 轮 = **1 分钟**的涨跌幅）。
  - 为什么改：单轮（5 秒）噪声就有 0.5%~1%，按单轮判定「1% 一档」几乎帧帧打满，
    虚假成交退化成无脑跟；1 分钟动量把噪声摊平，触发一次能维持约一分钟
  - 三段式（这就是「不会刹不住车」的三道闸）：
    1. **死区**：`|chg| < 1 档`（默认 3%）→ 买卖各半，小抖动不触发
    2. **线性**：1 档 → 0 偏移，2 档 → 满幅（追涨/杀跌系数，25 → 0.75）
    3. **过热回落**：> 3 档开始减弱、≥ 5 档归零 —— 短时间涨太多反而没人敢追
  - 外加**压力自限幅**：该票 `|st.mflow|` 越大偏向越弱（≥ 2 单位时只剩 40%），
    防止「自己推自己」越推越猛
  - 结果永远夹在 0.1~0.9；两个系数都填 0 = 永远各半；杀跌系数缺省跟随追涨系数
  - 管理面板：「行情节奏 → 虚假成交」里的 **判定窗口 / 触发幅度 / 追涨系数 / 杀跌系数**
  - **可按个股覆盖**（2026-11）：每只票在「个股 → 每只票」里有
    `mktWindow / mktTrigger / mktChase / mktPanic` 四个字段，填了就用个股的、
    **留空跟随全局**（`genMarketTrades` 里 `st.trait?.mktXxx ?? cfg.marketTradesXxx`）。
    面板上标签是「追涨杀跌·判定窗口 / 触发幅度 / 追涨系数 / 杀跌系数」，
    右侧标着「跟随全局」，输入框占位符直接显示当前的全局值
  - 举例（窗口 12 轮、trigger 0.03）：1 分钟涨 2% 不偏；涨 6% 买盘 75%；涨 12% 回到 62.5%；
    涨 20% 完全回到各半；跌 6% 卖盘 75%
- **散户情绪落地到成交里**（2026-11 新增，`marketTradeWeight()` / `marketSentimentBias()`）：
  以前情绪只偷偷改价格，成交记录里看不出来。现在三件事都作用在虚假成交上，
  **原来的成交机制一点没动**（三档金额、昵称头像池、走 `st.mflow` 推价、流水混在游资里）
  1. **谁在被交易：按流通市值分配**（`marketTradesSizeExp`，默认 1）
     `权重 = (流通市值 / 1亿) ^ 指数 × 个股倍率 × 情绪放量`
     —— 大票笔数多、小票笔数少，各票「成交额 ÷ 流通市值」接近，**推动力才拉得平**
     （原来是 9 笔在十几只票里均匀抽：小票被推飞、大票纹丝不动）
     指数填 0 = 退回老行为（每只票一样多）
  2. **方向：情绪定买卖**（`marketSentimentBias`，默认 25）
     `买盘概率 += 这个数/100 × 情绪值`（情绪 v=+1、填 25 → 买盘 +25pp，仍夹在 0.1~0.9）
  3. **放量：越兴奋成交越多**（`marketTradesSentVol`，默认 60）
     `笔数 ×(1 + 这个数/100 × |情绪|)`；全市场平均兴奋度还会抬高**总笔数**
     （全员 v=1 时总成交额约 ×1.6）
  - 个股可以在「个股 → 每只票」覆盖：`mktSizeExp / mktSizeScale / mktSentBias / mktSentVol`，
    **留空跟随全局**；`mktSizeScale` 是这只票的额外成交倍率（1 = 正常，2 = 翻倍）
  - 全局设置在「行情节奏 → 虚假成交」：按流通市值分配笔数 / 情绪方向权重 / 情绪放量
  - 测试：`node tests/sentiment-trades.mjs`（26 条：权重、放量、方向、端到端笔数分布）

- **指数的虚假成交**（2026-11 修）：指数本身没有 shares，marketTradeWeight 算出来只有 1e-8，
  抽签永远抽不到 → 指数页的成交记录/量能全是空的。现在指数单独算权重
  indexTradeWeight() = **成分股流通市值之和 × indexTradeScale（默认 0.08）**，约占总笔数的 15%
  - 成交记录记在指数上（code: DENG/DENGS），量能和冲击走 ddVolume / ddMarketFlow，
    两者都会**按成分股权重拆给每只成分股** → 指数单能间接推动成分股股价，成分股一动指数自然跟着动
  - indexTradeScale = 0 可完全关掉；面板在 **行情节奏 → 虚假成交 → 指数虚假成交权重**
  - 回归测试：	ests/index-trades.mjs（25 条）
- - **开盘巨量**（2026-11 新增，`reopenSurgeMult`，默认 3）：休市（夜间循环 / 定时计划 / 管理员休市）
  结束后的**第一轮**，虚假成交笔数 ×这个倍率（3 = 三倍量），之后立刻恢复正常
  - 实现：`server.js#loop` 在休市分支记 `db.marketWasClosed = true`，开市后第一轮置 `db.reopenSurge = true`；
    `genMarketTrades` 读到就放大 `base` 并清标记（只作用一轮，绝不复用）
  - 笔数放大 = 成交额、成交量、价格压力一起放大（推动仍受 `marketImpactMax` 单轮封顶约束，
    压力会按 `marketImpactDecay` 在后续几轮慢慢释放，形成「开盘一波量」
  - 倍率 0 或 1 = 不放量；上限夹在 10 倍（防手滑填个 1000）
  - 面板：**行情节奏 → 虚假成交 → 开盘巨量(休市后第一轮倍率)**
- - **金额分档**（`MARKET_TIERS`，写死在代码里）：权重是 `marketTradesSmallP / MidP / BigP`，
  三个数字只是权重、会自动归一化；全填 0 = 等概率。
  **出现频率 `marketTradesRate`（管理面板「行情节奏 → 虚假成交 → 出现频率」）就是每轮笔数的倍率：
  6 = 每轮 6~12 笔（平均 9 笔、约 450 万成交额，全部同向时单轮推动上限 ≈ 0.09%）；
  填 0 或总开关 `marketTradesEnabled: 0` = 彻底不生成**
  （以前倍率 0 还会硬编 1 笔，等于关不掉 —— 2026-11 一并修了）
- **游资**（`src/hotmoney.js`）：状态在 `db.hotMoney`
  `{ code, industry, nextSwitchTick, switches, startedTick }`，老存档由 `migrate` 补空壳，
  下一次 tick 自己开仓。板块 = 股票的 `industry` 字段（消费娱乐 / 科技AI / 金融…），
  优先换到**不同**板块；只有一个板块时就在原地换票。
  换板块间隔写 `nextSwitchTick = tick + rand(hotMoneySwitchMin, hotMoneySwitchMax)`，
  **闭区间**，所以 20 和 300 都可能抽到。旧票停牌/退市时卖不出去，但照样换板块买新的
- **价格通道**：两者都调 `trading.js#addMarketFlow(db, st, signedNotional)`，
  写进 `st.mflow`（单位 = `marketImpactRef`，默认一笔 1000 万 = 1 单位，上限 `marketImpactFlowMax`），
  由 `stepStock` 逐轮释放。**和玩家冲击 `st.flow` 是两套独立通道**，互相不抢上限
- **买指数**：虚假成交/游资也会打到 DENG / DENGS 上，按指数权重**拆给成分股**
  （`indexKeyFor()` 决定用 `index` 还是 `smallIndex` 的权重表 —— 以前 DENGS 错用了 DENG 的，
  2026-11 一并修了）
- **不进管理控制台**：游资行带 `isMarket: true`（`consoleRows` 只给真人单），
  另外带一个内部标记 `hot: true`，**这个字段不下发前端**
  （`/api/stock-trades` 是白名单式映射，只给 id/at/playerId/nickname/emoji/isMarket/action/…）
- **playerId 也用 `mkt_` 前缀**：接口会下发这个字段，游资不能露馅
- 参数全在管理面板：「行情节奏 → 虚假成交 / 游资资金」两组 + 「交易规则 → 市场冲击（玩家 vs 虚假成交 / 游资）」里的市场那一半
- 模拟与调参：`node tests/sim-market-flow.mjs`（单笔推动多少、方差占比、天花板、敏感性），
  回归：`node tests/market-money.mjs`（73 条）

### 6.9 公告（`engine.js#pushNotice` / `noticeAlive`）

公告存在 `db.notices`，字段：`{ id, text, at, tick, expireTick, kind?, href? }`。

- **一律用 `pushNotice(db, text, ticks, extra)` 发**，不要直接 `db.notices.push`
- `ticks` 是显示时长（轮），写入时换算成绝对轮次 `expireTick = tick + ticks`
  - `ticks = 0` → `expireTick = 0` → **永久**，不会自动消失
  - 发公告时顺手把已过期的清掉，超过 20 条丢最老的
- **是否可见统一用 `noticeAlive(db, n)`**，两处 payload（`marketPayload` / `tickPayload`）都用它过滤
  - 有 `expireTick` → `db.tick < expireTick`
  - 老公告（存档里的历史数据没有 `expireTick`）→ 退回原来的 24 小时时间口径
- 管理面板「发布公告」有「显示时长（轮，0 = 永久）」输入框，默认 720（≈1 小时）
- **盘面异动公告固定 30 轮**：`engine.js` 的 `LOTTERY_NOTICE_TICKS = 30`（抽奖分支 2026-11 已删，
  这个常量和它的公告调用一起下线，别再照着它写新公告）
- payload 里额外下发 `leftTicks`（还剩多少轮，永久为 `null`），前端据此显示「还剩 N 轮」
- **可跳转公告（2026-11 加）**：extra 里带 `href: '/tournament'` 就能让公告变成可点的
  - 清洗统一走 `noticeLink(n)`：只认单个 `/` 开头的站内路径，`//evil.com`、`https://`、`javascript:`
    以及含引号/尖括号的一律返回 `''`（公告是管理端输入，也当不可信处理）
  - 两处 payload 下发 `href`（没有就是 `null`），前端渲染成 `查看 ›` 小按钮
  - 管理面板有「跳转链接（可选）」输入框，非法地址后端直接 400
  - 上线发公告的写法见 `README.md` 的「发一条带跳转的公告」

### 6.10 自动定投（`autoDca.js`，Lv.2 道具）

- 玩家数据：`player.autoDca`（买过没有） + `player.autoDcaOn`（当前开没开，默认 true）
- 每轮 tick 在 `server.js` 的打工结算之后调 `autoDcaTick(db, bankCap)`：
  1. 钱袋 `workBank` 攒到上限 `bankCap`（默认 50 × 1440 = 72,000）
  2. 且没有未成交的定投单（`orders` 里 `autoDca: true` 的那张）
  3. 就自动把钱袋收进现金，并挂一张 **DENG** 买单
- 挂单价 = `DENG 现价 × (1 + shopAutoDcaPremium)`（默认 +3%，保证下一轮成交）
- 股数 = `钱袋 ÷ 挂单价`；押金按挂单价冻结，成交后差额自动退回现金
- **系统单**：`placeLimitOrder(..., { system: true })`，不占「同时挂几笔」名额，
  也不吃玩家每轮的操作次数
- 下单失败（比如玩家持有 DENG 空单）会把钱袋和现金原样退回，下一轮再试
- **离线也生效**：整段逻辑不看在线状态（打工离线是 ×1 速度，在线 ×2）
- 接口：`POST /api/shop/auto-dca`（购买，校验 Lv.2 + 现金）、
  `POST /api/shop/auto-dca/toggle` `{ on }`（暂停/继续）

### 6.11 丰川银行（`bank.js`）

- 玩家数据：`player.bank`（银行存款）+ `player.bankDeposited`（累计存入）
- **账号升级交的钱直接存进银行**，不再凭空消失：`levelUpPlayer()` 里
  `cash -= cost; bank += cost`
- ⚠️ **银行存款不计入 `playerEquity`**（`playerEquity` 不读 `p.bank`）。
  否则「总资产低于门槛」这个条件永远不成立，取钱功能就是摆设；
  等级门槛、升级费用、爆仓判定都按「不含存款」的口径走
- **唯一例外是排行榜**：`/api/leaderboard` 每行返回 `equity`（交易资产）、`bank`、
  `total = equity + bank`，**按 `total` 排序**，前端显示 total 并挂一个 🏦 余额小标
- **偷钱上限按「现金」算，不按总资产**（2026-11 改）：持仓里的钱偷不到，
  所以百分比挂在对方现金上——只持仓不剩现金的人被偷不到东西。
  算钱逻辑在 `src/steal.js#stealAmount()`，别在 `server.js` 里重写一遍
- **取钱救急**：`withdrawFromBank()`，条件 `总资产 < bankPoorThreshold`（默认 10 万）
  - 金额 = **存款 × 随机(`bankWithdrawRateMin`~`bankWithdrawRateMax`)**（默认 1%~20%），
    但不少于 `bankWithdrawFloor`（默认 10 万）；存款不足下限就取全部
  - 例：存款 2250 万 → 一次取 22.5 万 ~ 450 万；存款 100 万 → 10 万 ~ 20 万（下限托底）
  - 取完总资产会超过门槛，所以不能连点刷钱；
  - 银行存款是玩家自己升级交的钱，不构成凭空造钱
  - 状态接口返回 `withdrawMin` / `withdrawMax` 给前端显示区间（实际金额取款时才掷）
- 接口：`GET /api/bank`（状态）、`POST /api/bank/withdraw`（取钱）
- 前端：顶栏「银行」标签页（`#view-bank`），显示余额 / 累计存入 / 总资产 / 状态，
  以及一个「取出 $100,000」按钮（不满足条件时置灰 + 提示还差多少）
- **管理端「打钱」打到现金，不打银行**（2026-11 改）：`POST /api/admin/player { action: 'cash', amount }`，
  逻辑在 `api.js#grantCash()`。银行的钱要满足「总资产低于门槛」才取得出来，发补偿/活动奖励
  打进去玩家用不了，所以改成直接补现金
  - 现金不允许为负（扣到 0 为止），否则会连带影响爆仓判定
  - 返回的 `amount` 是**实际变动额**：现金已经是 0 时再扣就是 0，前端据此提示「扣不动」
  - 不动 `bank` / `bankDeposited`（后者是玩家自己升级存进去的累计值）
  - 旧的 `action: 'bank'` 分支保留给脚本 / 应急用，管理界面已不再调用

### 6.12.05 5 分钟也单独存了（2026-11）

以前 5 分钟只能从 `series` 现算：`series` 只留 `historyTicks`(3600) 个 tick = 5 小时，
一根 5 分钟要 60 个 tick → 最多 **60 根**，而 1 分钟图有 300 根，切过去就只剩一条小尾巴。

现在 5 分钟也有自己的数据包，**根数和 1 分钟对齐**：

| 周期 | 存哪 | 每根 tick | 根数 | 覆盖时长 |
|---|---|---|---|---|
| 1 分 | `series`（现算） | 12 | 300 | 5 小时 |
| **5 分** | **`bars5`** | **60** | **300** | **25 小时** |
| 15 分 | `bars15` | 180 | 192 | 48 小时 |

- `src/bars15.js` 重构成通用实现（`pushBar` / `seedBars` / `barsToCandles`），
  再导出 `pushBar5 / seedBars5 / bars5Candles` 和老的 `pushBar15 / seedBars15 / bars15Candles`
- 引擎每轮同时写 `bars5`（价格在 3.2 段、成交量在 3.65 段），指数也一样
- 老存档由 `migrate` 用 `seedBars5` 铺满 300 根（尾部接现价），版本号 `bars5Ver`
- 新接口 `/api/candles5?code=XXX`（结构同 `/api/candles15`）；
  前端 `candlesUrlFor()` 里 5m 走这个接口，不再用 `/api/candles?tf=5m`
- 测试：`node tests/candles5.mjs`（24 条）

### 6.12.1 15 分钟 K 线单独存 48 小时（`src/bars15.js`）

**问题**：所有周期都是从同一条 `series` 聚合的，而 `series` 只留 `historyTicks`(3600) 个
tick = 5 小时。15 分钟一根要 180 tick，所以 15m 最多只有 20 根。

**做法**：给每条 series 单独攒一份 15 分钟 K 线（环形缓冲，192 根 = 48 小时）。

- 存储：`st.bars15 = [[bucket, open, high, low, close], ...]`
  - `bucket = floor(absTick / 180)`，**不存时间戳** —— 返回时用 `timeFromAxis()`
    按真实时间轴换算，这样和别的周期共用同一套「停机空洞压缩」逻辑
- 收集：`stepMarket` 里每处 `series.push()` 后面紧跟
  `pushBar15(st.bars15, floor(tick/180), price)`（个股、DENG、DENGS 各一处）
  - 同一根就更新 high / low / close，跨桶新开一根，超过 192 根丢最老的
- 冷启动：`migrate` 里发现 `bars15` 为空（或 `bars15Ver` 落后）就 `seedBars15()`
  往回随机走 192 根，**尾部接上现价**（否则图上最后一根离现价很远）
  - 单根波动由 `seedVolFromConfig()` 从 `baseVolatility` 推：`σ_tick × √180 × 0.75`
    （1%/tick → 约 10%/根），再叠加每根 12% 的「往现价拉回」防止 48 小时跑成 10 倍
  - ⚠️ 踩过的坑：第一版用了固定 2.4%/根，比真实盘面（约 10%）安静太多，
    结果**最后一根真 K 线**在图上像一根突兀的大阳线，玩家以为数据读错了。
    改算法后把 `BAR15_SEED_VER` 加 1，`migrate` 会按新算法重铺老数据
  - ⚠️ 只对非指数票跑那段循环，**指数标的（DENG / DENGS）要单独补一遍**，
    否则灯的 15 分钟图是空的
- 接口：`GET /api/candles15?code=TGW` → `{ code, tf:'15m', candles:[...] }`
  （192 根，约 16 KB；不传 `tf`，也不用 `maxCandles` 裁剪）
- 前端：`loadCandles()` 里 `tf === '15m'` 时改走 `/api/candles15`，
  其它周期完全不动；每 tick 的更新逻辑（`applyTickToChart`）照旧，因为
  桶号算法一样（`floor(tick/180)`）
- 成本对比：只存 15m → db.json 约 +109 KB（11 条 × 192 根）；
  换成存 48 小时原始 tick 要 +2.9 MB，**差 20 多倍**
- 测试：`node tests/candles15.mjs`（32 条：更新/跨桶/封顶/冷启动/转换）

### 6.11.9 定时休市 / 循环作息（`src/schedule.js`，2026-11）

休市有三个来源，优先级从高到低：

| 来源 | 怎么配 | 说明 |
|---|---|---|
| 总开关 | `config.marketOpen = 0` | 管理员「立即休市」，谁都开不了，不会自动恢复（老行为） |
| **定时休市** | `db.marketSchedules` | 一次性（指定日期时间）/ 每天（HH:MM），每条带时长和备注，可停用/删除 |
| **循环作息** | `marketCycleEnabled/OpenMin/CloseMin` | 开 N 分钟、休 M 分钟，按现实时间无限循环。**默认开 5 / 休 2** |

- 唯一入口 `marketPhase(db, now)` → `{ open, reason, label, nextOpenAt, nextChangeAt, cycle }`，
  `reason` 是 `manual / schedule / cycle / open`
- 全部按**服务器本地现实时间**算，和 tick 无关：重启、卡顿、SSE 断线都不会把节奏带偏；
  循环用 `Math.floor(now/1000) % 总周期`，永久对齐整点
- 一次性计划过期后 `ensureSchedules()` 自动标 `done` + 停用（面板显示「已结束」并划掉）
- 每天计划支持**跨零点**（如 23:30 起休 90 分钟 → 次日 01:00 开市）：同时检查今天和昨天的窗口
- 休市期间：**只冻结行情和撮合** —— 挂单、止盈止损照常能挂（`orders.js#placeLimitOrder` 不再拒单，押金照冻），`server.js#loop` 走冻结分支（`stepMarket` 不跑、`db.tick` 不前进），
  下单接口直接 423「xxx，暂停交易」，每轮 payload 带 `closed/closedReason/closedLabel/closedUntil`
- 前端：顶部横幅显示原因 + `mm:ss 后开市` 倒计时；K 线 5 分钟档 = 一个交易日，标成「**5分（日K）**」
- 管理接口：`GET/POST /api/admin/schedule`（`action: add | del | toggle`），
  面板在「管理 → 市场 → 定时休市 / 开市」
- 测试：`node tests/market-schedule.mjs`（48 条：解析、清洗、一次性、每天、跨零点、循环、优先级）

### 6.12 K 线时间轴（`engine.js#tickTimeAxis`）

- `/api/candles` 的横轴**不再直接取 `tickTimes` 的原始时间戳**：服务器停机/重启期间没有 tick，
  相邻两轮的真实时间差可能是几小时，直接画出来就是「一大段空白 + 线跳过去」的假缺口
- `tickTimeAxis(db)` 从**最新一轮往回**走，把每个间隔夹在 `[0.25×tickMs, 3×tickMs]`：
  最新一根保持真实时间，历史空洞被压成正常几格，横轴永远连续递增
- `/api/equity-curve` 用同一条轴，收益曲线不会被停机拉断
- 客户端兜底：`applyTickToChart()` 发现**整整漏掉一根以上**（SSE 掉线 / 手机切后台被挂起），
  不再只补一根，而是 `resyncCandles()` 静默重拉一次并保持当前缩放位置

> ⚠️ 休市时 `db.tick` 不推进，所以按 tick 计时的公告在休市期间**不会过期**，开市后继续倒计时。

#### 6.12.0 图表库：lightweight-charts v5 多窗格（2026-11 升级）

图表库在 `public/vendor/lightweight-charts.js`，2026-11 从 **4.2.3 升到 5.x**（193 KB），
目的只有一个：**真·多窗格**（v4 只能靠 `scaleMargins` 把一张图的竖直空间切三段，
价格刻度会漏到成交量那一格里，很难看）。

- v5 API 和 v4 完全不兼容，画线一律走 `chart.addSeries(定义, 选项)`：
  `LightweightCharts.CandlestickSeries / LineSeries / HistogramSeries`（v4 的
  `addCandlestickSeries / addLineSeries / addHistogramSeries` 在 v5 里**不存在**，调用直接抛）
- 三个窗格：价格（第 0 个，默认）+ 成交量（`chart.addPane()`）+ MACD（再来一个），
  每个窗格**自带右侧坐标轴**，共用同一条时间轴和十字光标
- 高度用 `pane.setStretchFactor()` 按比例分：价格 4 : 成交量 1.1 : MACD 1.3；
  **关掉的窗格给 0**（会塌成 2px 的缝，不是彻底移除）
  ⚠️ **别和 `pane.setHeight()` 混用** —— 两个一起调会互相覆盖，实测窗格会一直保持 2px
- `layout.attributionLogo: false` 关掉左下角的 TradingView 角标（会压在成交量柱上）
- 指标计算在前端：MACD(12,26,9)，柱 = 2×(DIF−DEA)；成交量直接读 K 线里的 `volume`

#### 6.12.4 B/S 买卖点（v5 之后必须用 createSeriesMarkers）

K 线上的 B/S 标记在 v4 是 `series.setMarkers(markers)`，**v5 把这个方法从 series 上移走了**，
换成 `LightweightCharts.createSeriesMarkers(series, markers)`（返回一个带 `setMarkers` 的对象）。

升级 v5 时前端还留着 `typeof series.setMarkers !== 'function' \&\& return` 的老守卫，
结果**标记整块不显示**、也不报错（2026-11 修）。现在统一走 `markerApi()`：
优先 `createSeriesMarkers`，没有就退回 `series.setMarkers`（v4 兜底），
把手缓存在 `state.markersApi`，图表重建时清空。

#### 6.12.3 成交量与 MACD（2026-11）

- **成交量来自真实成交**：引擎每轮把这只票的成交量（玩家成交 + 虚假成交 + 游资，
  统一在 `trading.js#logTrade` 和 `marketTrades.js` 里累加到 `st.volTick`）汇总进
  `st.volSeries`（和 `series` 一一对应）；`candlesFromSeries()` 按 K 线桶求和，
  每根 K 线带 `volume`；15 分钟那根存在 `bars15` 的第 6 位
- **指数成交量（2026-11 修正）**：指数的成交按**成分股权重**拆给个股，指数自己的成交量 =
  **成分股本轮成交量之和**（不重复计算）
  - 为什么：以前指数上的单子只记在指数头上，玩家点进个股 K 线发现一根柱子都没有；
    反过来个股成交也不进指数，指数柱子只有它自己那几笔
  - `trading.js#addVolume(db, code, qty)` 是唯一入口（玩家 / 游资 / 虚假成交都走它）：
    指数单 → `qty × 权重` 拆到各成分股；普通票 → 记自己头上
  - `trading.js#indexTickVolume(db, indexKey, tickVol)` 算指数这一轮的量：
    遍历**正常交易中**的成分股求和（停牌的不算，和指数价格口径一致）
  - 于是一笔 1000 万砸在 DENG 上，9 个成分股的成交量柱都会动，指数柱 = 它们的和
- - 老存档 `migrate` 会把 `volSeries` 前面补 0 对齐 `series` 长度 ——
  **成交量从上线那一刻开始攒**，历史全是 0（截图里看到柱子只出现在右边就是这个原因）
- **量能实时刷新**（2026-11 修）：行情里每只票多下发一个 `vol`（本轮成交量，股），
  前端 `applyTickToChart` 把它累加到**当前那根 K 线**上（同一根累加、新一根用本轮量做起点），
  并且只 update 量能柱最后一根（不整段重画）。以前成交量要等重新拉 K 线才变，
  切到 1 分钟图看着就是「柱子半天不动」
- 前端开关：「成交量 / MACD」两个按钮，状态存 `localStorage.xd_ind`，
  开着的指标在价格窗格下面各占一个窗格
- 切周期 / 切股票 / 每轮 tick 都会重算（同一根 K 线内重算 MACD，开新一根也重算）

#### 6.12.2 K 线叠加（2026-11）

同花顺那种「把另一只票 / 指数的 K 线叠在同一张图上」的功能，纯前端实现，**没有新增接口**
（复用 `/api/candles` 与 `/api/candles15`，同一周期、同一时间轴）。

- 入口：图表工具栏右侧「＋ 叠加」→ 面板列出**指数 + 全部个股**（当前标的不允许叠自己，置灰）
- 叠加的那份画成**蓝色 K 线**，挂 `priceScaleId: 'left'`：
  - 左轴单独按它自己的价格区间缩放，右轴仍是主图
  - 两侧 `scaleMargins` 上下错开（右 `top .32`、左 `top .06`），两组 K 线不会糊在一起
- 图上胶囊 `#ovChip` 显示「● 名称 代码 现价 涨跌幅 · 左轴 ×」，「×」取消叠加
- 叠加标的存 `localStorage.xd_overlay`，**刷新后自动恢复**；切到和叠加同一只票时自动取消
- 切周期 / 换主图标的都会重拉叠加数据；每轮 tick 用行情里的最新价推一下叠加的最后一根 K 线
  （`applyTickToOverlay()`，和主图 `applyTickToChart()` 一样按 K 线桶判断）
- ⚠️ 叠加数据的时间范围要**裁到主图起点之后**，否则时间轴被撑长、主图会被挤到右边一小块
- 相关代码：`public/app.js` 的 `ensureOverlaySeries / loadOverlay / setOverlay / restoreOverlay /
  applyTickToOverlay / renderOverlayChip`，样式在 `styles.css` 的 `.ov-*`
- 截图：`docs/screenshots/kline-overlay-*.png`（选择面板 / 叠加生效 / 整页 / 切 5 分钟）

### 6.13.1 主题 = 外观 + 技能（`/api/shop/theme`）

主题拆成了**两个独立的字段**，商城卡片上也是两个按钮：

| 字段 | 管什么 | 冷却 |
|---|---|---|
| `player.theme` | 只影响**配色/皮肤**（前端 `applyTheme()`） | **没有冷却**，随时换 |
| `player.skill` | 技能效果：红牛/绿熊平仓返现、暗黑冲击 +5%、大鳄财报预览、隐世成交隐藏、暗中调查、情绪读心、夜行者偷钱 | `shopThemeCooldown`（默认 100 轮） |

- 接口：`POST /api/shop/theme { theme, part }`
  - `part:'look'` → 只换外观，**不检查冷却**，不动 `skill`

  - `part` 省略 → 两者都换（老行为）

- 冷却字段 `skillChangedTick`：**`-1` = 从没换过技能**（`0` 是合法 tick，

### 6.16 偷钱（`src/steal.js` + `/api/steal`）

- **流程**：`POST /api/steal { targetId }` → 只写 `me.stealQueued`（当轮标记） →
  下一轮 tick 在 `server.js` 结算，得手才进冷却
- **金额**（`stealAmount()`，纯函数，测试在 `tests/steal-cash.mjs`）：

  ```
  每次金额 = min( 随机[stealMin, stealMax], 对方现金 × stealCapRatio, 对方现金 )
—— **不是固定百分比**：比例只用来封顶，实际是「随机金额，最多不超过他现金的 0.1%」
  目标 = 随机取 stealMin ~ stealMax（默认 100 ~ 10,000）
  实得 = floor(min(目标, 上限, 对方现金))
  ```

  - ⚠️ **百分比挂现金，不挂总资产**：持仓里的钱偷不到。
    只看总资产会出现「他全是持仓、一分现金没有，还能被偷走 1000」的荒谬情况
  - 现金 < 1 或算出来 < 1 块 → 算空手，**不进冷却**（空手不罚）
  - 冷却按人算：`stealCooldownFor()`，夜行者主题在夜里 60 轮 → 50 轮（进化后 20 轮）
- **拦谁**：隐身的号（`hiddenRank`）不能点名；有保镖（`guardUntil`）的偷不到；
  自己不能偷自己
- **流水**：得手后双方各记一条 `action: 'steal'`
- 测试：`node tests/steal-cash.mjs`（22 条：上限挂现金、跟持仓无关、随机区间、脏参数）

### 6.17 表情互动（`src/emoji.js`）

个股/指数详情页标题旁的 😀 按钮，点开是「我的表情」（带滚轮的网格），
点一个就发给全场：**所有玩家下一轮 tick 会在页面随机位置看到它从小放大冒出来**，
持续一轮后消失。

**规则**

- **一只票一个互动区**：表情带 `code`，客户端只显示 `code === state.code` 的那些
  （`filterEmotesByCode()` / 前端 `renderEmotes()` 里那行 filter）。
  在 TGW 页面看不到 MCD 的表情；切股票时 `clearEmoteFloats()` 把上一只票正在飘的清掉
- 表情按账号等级分层：`EMO_TIERS = [{ level:1, dir:'emo_lv1', files:[...] }]`，
  以后加 `emo_lv2` 就把 `level` 调高，`unlockedEmojis(level)` 会自动只给高等级玩家
- **只能发白名单里的文件名**（`isEmojiUnlocked()`），乱传 / 路径穿越一律 400
- **同一轮点多少次都只算最后一个**：`pushEmote()` 发现这个玩家本轮已经发过，就直接改自己那条
- 一轮最多 `EMOTE_PER_TICK_MAX`(12) 条、db 里最多留 `EMOTE_MAX`(60) 条，超出丢最老的

**「只活一轮」怎么实现**

```
玩家在 tick T 点表情 → db.emotes 里记 tick = T
tick T+1 的 payload（tickPayload / marketPayload）里下发 tick === T 的那批 → 全场冒出来
tick T+2 就不在筛选结果里了 → 自动消失
```

也就是 `visibleEmotes(db)` 只返回 `tick === db.tick - 1` 的那批；
前端对应 4.8 秒的 `emoFloat` 动画，到点自己 `remove()`。

**接口与下发**

- `POST /api/emote { emo, code }` → `{ ok, replaced, tick, emo }`
- `marketPayload` / `tickPayload` 顶层都有 `emotes: [{ id, nickname, emo, dir, code }]`
  （**全局那一批**都下发，前端按当前 `code` 过滤 —— 服务端不知道每个浏览器在看哪只票）
- `publicPlayer.me.emojis` = 该玩家解锁的文件名数组；`config.emojiDirs` 是档位目录映射
- 前端：`renderEmotes()` 把新表情插进 `#emoLayer`（fixed 层），随机 `left/top` + 随机旋转，
  动画 `emoPop`（0.15 → 1.12 → 1）接 `emoFloat`（轻微上浮 + 淡出）

**前端细节**

- 按钮在 `.chart-title` 里（股票名右边）；`@media (max-width:720px)` 时 `flex-basis:100%`
  掉到名字下面一行
- 面板点外部关闭、切股票自动关（`selectStock` 里 `toggleEmoPanel(false)`）
- 连点不排队：每次点击直接 POST，服务端覆盖自己上一条 = 「最后一个生效」

- 测试：`node tests/emote.mjs`（39 条：解锁、白名单、last-wins、可见窗口、按票过滤、上限、脏数据）

### 6.18 早市冲量（LU 瑞幸咖啡专属）

原来的「反转王」已经下线（阈值 72 轮连击永远达不到，而且方向和描述相反），
LU 换成**早市冲量**：`trait.id = 'morning'`。

**机制**（`engine.js#morningRallyWindow` + `applyMorningRally`）

- 每天 `morningRallyStartHour` ~ `morningRallyEndHour`（默认 **6:00~10:00**，服务器本地时间，
  支持跨零点）之间生效
- 进窗口那一轮记下基准价 `st.morningBase`（配 `st.morningSlot` 记日期，换天就重记）
- 目标价 = `基准 × (1 + total × 进度)`，进度从 0 线性走到 1 → **4 小时匀速爬坡**
- **只托不压**：只有价格低于目标价时才往上推；已经高于目标（比如玩家刚拉过）
  就一点都不动，绝不会主动往下压
- 每轮最多贴近 `morningRallyPull`（对数），所以是「托着走」而不是瞬移；
  pull 小于斜坡速度时追不满，终点会低于 total

**参数全在管理面板「个股 → 早市冲量（瑞幸 LU 专属）」**（`src/config.js` 默认值）：

| key | 默认 | 含义 |
|---|---|---|
| `morningRallyEnabled` | 1 | 开关 |
| `morningRallyStartHour` | 6 | 窗口开始（0~23） |
| `morningRallyEndHour` | 10 | 窗口结束（0~23） |
| `morningRallyTotal` | 0.25 | 窗口内累计目标涨幅（+25%） |
| `morningRallyPull` | 0.02 | 每轮最多向目标贴近多少 |

### 6.18.1 金价与矿工银行（MB）

- **金价是游戏内模拟的**（`src/gold.js`），不接外部接口：一轮 5 秒、财报 1 小时，
  真实金价一小时基本不动，接进来 MB 的财报会变成一条直线，玩家也看不出因果。
- 每轮 `stepGold(db)`：对数随机游走 + 向 `goldBase` 回归，状态在 `db.gold`
  （`price / base / reportBase / series`），参数在管理面板「金价（矿工银行）」。
- MB 的财报（`fundamentals.js#genNextReport`，`trait === 'gold'`）：

  ```
  增速 = 金价自上一期发报以来的涨跌 × goldCoef    （可预期）
       + U(−goldJitter, +goldJitter)              （随机浮动 = 超预期/不及预期的来源）
  ```

  净利率也会跟着金价小幅走（±3pp）。2026-11 起「预期」改按最近 5 期财报走势拟合，
  所以「超预期 / 不及预期」= 实际 − 走势外推（金价突变就是最大的意外来源）。
- 发报后 `db.gold.reportBase` 推到当前价，下一期重新起算。
- **市值剧本**：股本是 10 亿股、上市价 100 → **初始市值 1000 亿**；
  `capTarget = 3000 亿`、`capTargetRate = 0.08`，每期收掉 8% 的差距
  （首期 +16%，20 期前后到 2700 亿，30~40 期稳定在 2900~3000 亿，不会冲过头）。
  有 `capTarget` 时财报增速 = **目标增速 + 金价那段 + 随机浮动**；
  预期走走势拟合之后，这几段都不再直接决定「超预期」——金价突然涨/跌才是意外。
- **特性对外隐藏**（`seed.traitHidden`）：
  - 详情页**不显示金价条**（`renderChartSub` 只管 fx，MB 走隐藏分支）
  - `/api/market` 与每轮 tick **不下发 `gold`**（金价只在服务端流动）
  - 公开 payload 里 MB 的 `trait` 只留 `{id, volMult, revMult}`，`traitName` 为空 ——
    玩家看不到「金价驱动」这个名字和说明，只能从财报波动里自己摸规律
  - 金价系数 / 随机浮动**只走全局配置**（`goldCoef` / `goldJitter`，管理面板可调），
    不再存在个股 trait 里，避免两个旋钮打架

### 6.18.2 退市标的清理（LMFX）

`src/stocks.js` 里删掉标的后，`store.js#migrate` 会：

1. 找出「代码里没有、存档里还在」的标的；
2. 按最后价格把玩家持仓平掉（退回保证金 + 盈亏）；
3. 撤掉这只票的挂单（退回押金）；
4. 再删除行情对象（指数权重按现存票算，会自动失效）。

这样老存档不会留下「查不到行情」的孤儿持仓。清理只在 `migrate` 里做一次，重复启动不会二次结算。

### 6.18.3 肯德基（KFC）：反向跟随 + 疯狂星期四

两条规则都在 `src/kfc.js`（纯逻辑，方便单测）：

1. **反向跟随**（`engine.js#stepStock`，`trait.id === 'mirror'`）

   ```
   logRet += −clamp(麦当劳上一轮涨跌幅, ±20%) × mirrorCoef
   ```

   - 麦当劳这一轮涨多少，肯德基就往反方向走多少（默认系数 1）
   - 读的是**上一轮**的涨跌幅：`stepMarket` 每轮开头把各票的 `st.lastRet` 快照进
     `db.prevReturns`，所以结果不受遍历顺序影响（谁先算都一样）
   - 单轮最多吃 ±20%，避免对方一次暴动把它甩飞

2. **疯狂星期四**（`kfc.js#kfcRallyStep`）

   - 每个星期四 **11:00~13:00** 之间**随机挑一轮**，那一轮固定 **+50%**
   - 进入窗口时抽好具体时刻存进 `st.kfcRallyAt`，`st.kfcWeek` 记住是哪一周、`st.kfcFired` 记住有没有用过
   - 所以整周只来一次；服务器重启也不会重复触发（同一周 `kfcWeek` 不变就不用重新抽）
   - 触发时往 `db.notices` 推一条「🍗 肯德基疯狂星期四」，并打一行日志

3. **市值剧本**：8 亿股 × 100 = **800 亿**起步，`capTarget = 1000 亿`、`capTargetRate = 0.08`，
   40 期左右稳定在 990~1000 亿（实测 800 → 899(8 期) → 997(24 期) → 992(40 期)）。

- 判定挂点全在 `trading.js`：
  - 开仓时把「偏离价值线」和「单笔建仓额」记进持仓：
    `pos.valueArm`（偏离够远 + 金额够大）、`pos.valueHoldArm`（金额够大）、`pos.openNotional`（累计建仓额）
  - 平仓时按四条规则 `bumpGlobal()`：`valueCrossClose` / `valueHoldProfit` / `dragonNextTick` / `dragonFast100`
- 排行榜图标：`achvEmojiList(player)` = 主题图标（两条都达成）+ 全局成就图标（已达成）
- **完成弹窗**：payload 里的 `me.achv.unlocked` 是所有已解锁成就的扁平清单
  （`{id,name,emoji,desc,tone,kind,at}`），前端每轮拿它跟 `localStorage.xd_achv_seen` 求差集：
  - 首次拿到快照只登记、不弹（否则登录瞬间会把历史成就全弹一遍）
  - 之后出现新 id → `pushAchvToast()` 从顶部滑下一张卡，按 `tone` 上色
    （`theme` 青绿 / `value` 紫 / `dragon` 橙红），5.2 秒自动消失，点卡片跳成就页
  - `at` 只用于排查，弹窗判定靠 seen 集合；换成 `requireAll` 或改阈值后老成就会重新结算，
    但已经在 seen 里的不会再弹

**四个容易踩的坑**

1. **计数目标和金额阈值是两个键**：黑手的「累计开仓额」是 `achvDarkHandTarget`（1000 万），
   成就进度计的是「成功次数」`achvDarkHandCount`（1 次）。混用会永远不解锁。
2. `previewIn` / `preview` 现在**按玩家的进化阶数**算提前量，`api.js` 与 `server.js` 都要用
   `tycoonLeadTicks(db, player)`，别再写死 20。
3. 隐世隐身概率必须用**稳定哈希**（单号 → 0~999），否则同一笔成交每次刷新都在闪现。
4. 排行榜资产模糊只影响展示（`fuzzed`），偷钱上限仍按真实 `equity` 算。
5. **`x + 1e-9 <= 上限` 是反的**：窗口边界要写 `x <= 上限 + 1e-9`。
   2026-11 写「10 分钟内平仓」时写成前者，刚好 120 轮会被判成超窗（测试当场抓到）。
6. **读心读数现在按玩家判定**：`st.sentiment.viewV` 只是「假读数候选」，谁看到真值谁看到假
   由 `src/mind.js#maskSentiment(st, db, player)` 用「玩家+股票+重掷周期」的稳定哈希决定
   （未进化 50% / Ⅱ 阶 70%）。别再读 `viewV` 判断真假，也别在 tick 里 Math.random（会每轮闪）。
7. 全局成就的阈值必须 **> 0**：`achvTarget()` 把 ≤0 当成「没配」并回退默认值，
   别用 `-1000` 去「关掉」门槛（想关就把比较写成恒真，或者调小正数）。

### 数据包白名单（`src/wire.js`）—— 防作弊的唯一出口

**原则：只发界面上真的会画出来的字段。** 引擎内部状态一律不下发，否则 F12 就能算出未来。

| 函数 | 干什么 |
|---|---|
| `stockWire(db, st, me)` | 每轮字段：价格/涨跌幅/各周期 changes/ST/dps/payout/财报倒计时/大鳄预览/情绪 |

| `positionWire(pos, st)` | 持仓（首屏/每轮/止盈止损接口共用） |
| `traitWire(st)` | 个股只留 `{id}`，且**只有 `fx` / `broker`** 两个 id 有意义 |
| `reportWire(st)` | 财报只留界面字段（估值 fair、营收、净利、EPS/BPS、ROE、负债率、增速、期数、**市场预期 `expectedGrowth`**、history） |

**明确不下发**（`tests/payload-wire.mjs` 会拦）：

- 价格模型参数：`trait.volMult / revMult / drift / lotteryChance / floorRatio / mirrorCoef / steadyGrowth / rallyBoost / eventMult`

1. 先在 `public/app.js` 里确认有读取（`grep` 一下），没有就别加
2. 加进 `src/wire.js` 的对应投影（或 `CONFIG_KEYS`）

### K 线悬停信息（`#hoverInfo`）

拖动 K 线时显示 时间/开/高/低/收/涨跌幅/振幅，七项。**这个盒子高度是写死的**
（桌面 22px、≤900px 时 42px 两行），因为它在图表上方，高度一变图表就会跟着重排（hover 时狂抖）。
所以：
- 内容放不下时会被 `overflow:hidden` **裁掉**（手机端曾因此看不到涨跌幅）
- 加内容前先量 `scrollHeight`：超了就把高度一起调，或者按宽度隐藏次要项
  （≤380px 目前隐藏「振幅」，保住涨跌幅）

### 金额显示（`money` / `money0` / `moneyExact`）

全站金额统一走这三个函数，**别自己拼 `$` 和 `toLocaleString`**：

| 函数 | 行为 | 用在哪 |
|---|---|---|
| `money(v)` | 百万以上缩写：`$1.23M` / `$12.3M` / `$123M` / `$2.50B` / `$1.20T`；不足百万走 `$12,345.67` | 总资产、盈亏、成交额… |
| `money0(v)` | 同上，但整数位（无小数） | 商城价格、按钮上的「还差多少钱」 |
| `moneyExact(v)` | 永远完整千分位 | `title` 提示（缩写后悬停看全） |

- 缩写规则：`M`(1e6) → `B`(1e9) → `T`(1e12)，保留 **3 位有效数字**；
  `999.6M` 会自动进位成 `1.00B`
- **只缩 ≥ 100 万**：下单金额、手续费这些小数目保持原样，不然 `$348.19` 变 `$348.19` 也能缩成 `$0.35K` 就看不清了
- 顶栏总资产带 `title=moneyExact(...)`，所以悬停能看到精确值；新增展示大额的地方建议照做

## 9.6 锦标赛（`/tournament`）

独立赛区，和主市场**完全隔离**——一套自己的账、自己的价格、自己的排行榜，
不碰 `db.players` / `db.stocks`，主市场一行都不受影响。

### 文件与入口

| 位置 | 作用 |
|---|---|
| `src/tour.js` | 赛区全部逻辑（开赛、价格、成交、爆仓、打工、夺冠、快照） |
| `public/tournament.html` / `tour.css` / `tour.js` | 独立页面，四个标签：首页 / 行情 / 我的 / 排行榜 |
| `server.js` | 路由 `/tournament`（`/tour` 别名）→ `tournament.html`；主循环末尾调 `tourTick(db)` |
| `src/api.js` | `GET /api/tour`、`POST /api/tour/order`、`POST /api/tour/job` |
| `src/store.js` | `createDb()` 建 `tour`；`migrate()` 里 `ensureTour()` 给老存档补字段 |

页面不注入主站 `app.js`，**只借用主站登录态**（`localStorage.xd_token`）：
`GET /api/tour` 带 token 就返回个人账，不带就只返回公共行情和排行榜。

### 数据模型（`db.tour`）

```
startAt / startedAt / endedAt / frozen / tick / winner
fx      { rate, at, source, stale }       实时 AUD/JPY（抓取结果）
stock   { code:'LMFX', price, prev, series[] }
players { [playerId]: { cash, startCash, positions, jobs, opens, closes, liquidations, log[] } }
trades  []                                最近 120 条成交
```

**开赛时间**：`nextStartAt()` 取下一个服务器本地 21:00（已经过点就顺延到明晚），
建档时写进 `startAt`。`tourTick` 到点自动把 `startedAt` 置上并开始记 `tick`。

**赛前也会走图**：`tourTick` 在 `startedAt === 0` 时仍然调 `stepPrice`（走势序列照常积累），
但不加 `tick`、不结算、不判胜；下单被 `guard()` 拦住（「还有约 N 分钟」），
所以玩家能提前看到真实报价在动，却不能提前建仓。前端 `frozenTag` 此时显示「赛前走势」。

### 价格：股价就是实时汇率

报价**不做任何加工**，就是抓到的 AUD/JPY 原值，保留 3 位小数（109.018，和零售外汇报价一致）。

链路：`server.js#startFxLoop` → `refreshFx()` → `src/fx.js#fetchAudJpy()`

- **抓取频率**：主市场没有 fx 票时按 10 秒一次（下限 15 秒）；一次抓取同时写
  `db.fx`（主市场）和 `db.tour.fx`（锦标赛），不重复请求
- **数据源**：先 Swissquote `forex-data-feed`，失败退到 `fxratesapi`，两个都挂就沿用上一次的值
- **写入**：`setTourRate(db, rate, at, source)`；`rate <= 0` 只把 `stale` 标上，价格绝不自己编
- **推进**：`stepPrice()` 读 `t.fx.rate` 写 `t.stock.price`，**每轮落一个点**——
  汇率 10 秒才更新一次，价格没变时那一轮就是平线，时间轴才和真实分时图一致
  （序列上限 900 点，约 75 分钟滑窗；快照只下发最近 240 点）
- **没接上时**：`guard()` 直接拒绝下单（`汇率还没接上，稍后再试`），前端 `frozenTag` 显示「汇率更新中断」

没有随机游走、没有跳空、没有基准归一化 —— 图上的曲线就是 AUD/JPY 本身。

**图表**：和主站同一套 `lightweight-charts`（`/vendor/lightweight-charts.js`），
配置、网格、十字光标、涨跌色全部照抄主站 K 线面板。

- 报价点每 5 秒一个，**12 个点聚成一根 1 分钟 K 线**（和主站 `1m` 周期同口径）
- 面板顶栏有 **1分 / 5分 / 15分** 三个周期，都是同一份报价点在本地重新聚合，不额外请求后端
- **MA5 / MA10 / MA30** 在前端算（收盘价简单均值），颜色照抄主站的橙/蓝/紫
- `stock.seriesAt` 存每个点的时间戳（毫秒），前端拿它当 x 轴；老存档缺这半边时
  按 `tickMs` 反推补齐，所以停机留下的断档在图上会如实空出来
- 数据不足一屏时手动定 `setVisibleLogicalRange`，左右各留一点空，现价标签和时间轴刻度才不被裁
- 换周期后不足两根 K 线时先把图**清空**再显示「正在攒第一根 K 线」，
  否则会留着上一个周期的旧柱子，提示叠在上面像卡住了

> 注意：真实汇率一天通常只走 0.5%~1%，1000 倍杠杆满仓下汇率逆向 0.095% 就爆仓（约 100 秒一轮），
> 而「30 万 → 2000 万（66.7 倍）」要汇率单向涨 6.57%。所以这本质是一场高频赌博：
> 押对方向 0.1% 就翻倍，押错就归零，连续对 6~7 次才能到 2000 万。

### 行情页布局（照搬主站个股页）

赛区的「行情」标签就是主站 `#view-market` 里那张个股页，**结构、类名、样式数值都不改**：

- 上：`.market-grid` = 左 `.chart-panel`（标题 / 周期 / 均线 / 报价源条 / 图）+ 右 `.trade-panel`
- 下：`.positions-panel` 我的持仓表（标的 / 方向 / 数量 / 杠杆 / 成本 / 现价 / 浮动盈亏 / 保证金 / 爆仓价，
  底部一条现金行），和主站 `#positionsTable` 同一套表格
- 下单栏：`下单 / 成交记录` 两个页签（主站的止盈止损赛区用不上，**整块隐藏**）、
  开仓/平仓切换、做多/做空、数量 + 快捷仓位、杠杆滑条（绿→红渐变）+ 快捷档、成本区三行
- 主站面板里用不上的东西（挂单价、让利、简单模式、传统挂单、手续费、冲击成本、我的挂单）
  一律不渲染，不留死按钮
- 样式是从 `public/styles.css` **原样摘进** `tour.css` 的（`--soft / --hl-* / --bd-*` 那批变量也一起补进 `:root`），
  改主站那边不会影响赛区；两边要同步时得手动对着改
- 两个类名冲突点：卡片用 `.panel`（所以四个 tab 的容器改叫 `.tab-panel`），
  代码标签 `.chip` 只在 `.chart-title` 里覆盖，别动顶栏的赛区状态 chip

### 交易规则

- 起手 30 万日元，1~1000 倍杠杆，做多/做空，**零手续费**（`TOUR_FEE_RATE = 0`）
- 下单面板有 20/100/500/1000 四个快捷档（滑条 1~1000 拖不准），并实时算「爆仓价位」
- 成交是**市价即成交**（不是挂单），**不带任何资金冲击**（价格只跟汇率走）
- 保证金剩 5% 时强平（`settleOne`），现金不会为负
- 打工：现金 < 30 万时一次补齐到 30 万，**次数不限**（`tourJob`）
- 第一个 `tourEquity >= 2000 万` 的人夺冠 → `frozen = true`，
  价格、tick、下单、打工一起冻结，排行榜定格

## 12. 已知坑（血泪清单，动手前必读）

### 12.1 编辑文件

- **中文内容一律用 `write` 工具，或用 Python 以 `newline='\n'` 写入**
- **不要在 PowerShell 里内联 Python 传中文/引号**（会被解析成命令，报一堆 “无法识别” 错误）→ 先写临时 `.py` 文件再执行，跑完删除
- **不要用花括号配对来删函数/代码块**——之前删划线功能时用正则匹配括号，误删了 `placeLimit` 等函数导致整页崩溃
  正确做法：按行号定位 → 只删目标区间 → 删完 grep 一遍关键函数名确认还在 → `node --check`

### 12.2 前端

- **`hidden` class 会被 `.shop-grid { display: grid }` 覆盖**（特异性相同，后者更靠后）→ 切显隐时用 `el.style.display = 'none'/''` 兜底
- **DOM 嵌套错误会静默失效**：父元素被 `display:none` 时，子元素无论怎么设置都看不见。改完 HTML 结构要数 `<div>` 和 `</div>` 是否配平
- **改静态资源必须 bump `sw.js` 的 CACHE**，否则用户看到的还是旧文件（典型症状：「改了没生效」）

### 12.3 服务端

- **兄弟股同轮发报**：`sib.nextReportTick` 必须设成 `db.tick`（当前值），不能赋 `st.nextReportTick`（旧值）——否则会每 tick 都发报
- **小灯指数调仓**：判定用 `db.tick === idx.rebalanceTick`，不能用 `>=`（会每轮触发，指数锁死）
- **指数标的（DENG/DENGS）不走 `stepStock`**，所以它们的 `series` 要在指数计算处手动 push，否则涨跌幅恒为 0
- **`0` 与 `undefined`**：`Number(cfg.x) || fallback` 会把合法的 0 吞掉，用 `??` 或显式判断
- **止盈止损不能走限价撮合**：跳空时卖单永远不成交（止损失效），auto 单必须强制成交
- **押金必须含冲击成本**：`estimateReserve()` 漏了 `impactCost`，全仓挂单会在成交那一刻报「现金不足」并撤单
- **「每人每轮 N 次」这类限制必须真的调用**：`orderLimitBlocked()` 定义了却没人调用，等于没限制

### 12.4 个股面板

个股参数只在 `public/app.js` 的 **`TRAIT_LABELS` 白名单**里出现的 key 才会渲染。新增个股级参数时：
1. 在 `TRAIT_LABELS` 加 `key: ['中文名', '提示']`
2. 在 `store.js#migrate` 给每只票补默认值（否则老票没有这个字段，面板不显示）

## 14. 最近的关键修复（了解历史，避免重蹈覆辙）

| 问题 | 根因 | 修复 |
|---|---|---|
| 农业股每 tick 发报 | 兄弟股同步用了旧 tick | 改成 `db.tick` |
| 小灯指数锁死 1000 | 调仓条件 `>=` 恒真 | 改成 `===` |
| 小灯指数涨跌幅恒 0 | 指数标的 series 不累积 | 指数计算处手动 push |
| 排行榜持仓串位 | 表头 6 列、行只有 5 个 td | 补上等级 td |
| 止盈止损串单 | 切股票未重渲染列表 | `selectStock` 里调 `renderStopLoss` |
| 商城 Lv.2 空白 | tier2 网格嵌在 tier1 内部 | 运行时 `normalizeShopDom()` 强制平级 |
| 金融大鳄预览不刷新 | `tickPayload(null)` 是公共 base，按人算的 `preview` 不在里面 | 广播时按玩家 `theme === 'tycoon'` 单独合并 stocks[].preview |
| 抽奖股财报好却一直跌 | 抽奖用「涨 ×(1+p)/跌 ×(1−p)」，对数期望恒负（−3.5%/次） | 下跌改成 ×1/(1+p)，与上涨互为倒数，零漂移 |
| 熊主题提示显示牛图标 | toast 文案写死 | 按 `me.theme` 判断 |
| 熊主题累计返现为 0 | payload 漏 `bearBonusEarned` | 两处 payload 都补 |
| 管理页改的公告不显示 | tick 不同步 `notices` | `onTick` 合并 `d.notices` |
| 部分个股图标 404 | 兜底路径拼 `.png` | 优先取 `state.market.stocks[code].icon` |
| 挂单不成交 | 误判 `maxOrdersPerTick` 是全局成交上限 | 实为「每人每轮操作次数」，恢复为 5 |
| 商城 Lv.2 整块消失 | `#shopGrid2` 嵌在 tier1 网格里（DOM 嵌套错误） | 商店改版时重排成三个平级 `[data-shop-panel]`，删掉运行时搬家的 hack |
| 等级不够也能买 Lv.2 商品 | 只有前端隐藏，接口没拦 | 统一 `shopGate()`，6 个下单接口全部前置校验 |
| 商城数字不实时 | 只在切页面时渲染 | `onTick` 里每轮 `renderShop()`，顶部加现金条 |
| 财报报假增速 | 报的是夹之前的 `expectedGrowth` | `growth` 改为营收真实变化 |
| 全市场增速趴地板 | `bias` 只偏不回归 | 每期回归 15% + 低基数反弹 |
| 新票上市带假历史 | `migrate` 给 `period < 6` 补了假财报 | 新票不回填并清理 `backfill` 记录 |
| 弦卷财团到不了目标市值 | `migrate` 不同步 `capTarget`，且 BPS 地板托住 fair | 种子字段一律同步 + 营收/净资产/合理价三处一起收敛 |
| 15m K 线全是「大阳线」 | 种出来的历史 σ 只有 2.4%/根，真实约 10% | `seedVolFromConfig()` 按 `tickVol×√180×0.75` 生成，`BAR15_SEED_VER` 触发重种 |
| 同票能一边开仓一边平仓 | 只检查持仓方向，没检查在挂的单 | `pendingConflict()`：开仓挡手动平仓单，平仓挡开仓单/重复平仓 |
| 让利 >10% 的开仓不成交 | 曾把「挂价高于市价 10%」当「到价才买」撮合 | **整段回退**，限价单恢复「按市价成交」的标准语义 |
| 挂价上限挡住正常开仓 | 曾加「开多挂价 ≤ 现价 100%」的拒绝逻辑 | 同样回退；现行为 = 任何价位都能挂 |
| 管理页一屏到底 | 6 个面板平铺、参数 100 项挤在一起 | 顶部 5 标签（控制台/市场/个股/玩家/参数），参数再分 7 大类 |
| 管理页看不到真人成交 | 只有全局 `/api/trades` 流水 | 新增 `/api/admin/console`（真人单 / 增量游标 / 近 1 小时汇总） |
| 表情挤乱手机端布局 | 按钮用 `flex-basis:100%` 占了一整行 | 手机端绝对定位到标题栏右上角，断点与 `isMobile()` 统一成 760px |
| 表情跨股票串台 | 只按 tick 过滤，没管是哪只票的 | 表情带 `code`，前端 `filterEmotesByCode()` 过滤，切票清屏 |
| 换外观也要等冷却 | `theme` 一个字段同时管皮肤和技能 | 拆成 `theme` / `skill`，只有换技能吃 `shopThemeCooldown` |

| 虚假成交关不掉 | 倍率 0 时 `Math.max(1, …)` 还会硬编 1 笔 | `rate <= 0` 直接 return；`marketTradesEnabled: 0` 也拦 |

| 买小灯指数推错成分股 | 分钱时一律读 `db.index.weights` | `indexKeyFor(st)`：DENGS 走 `smallIndex` 权重表 |

## 16. 给下一位维护者的建议

1. **改之前先读代码，不要凭记忆改**——这个项目迭代了很多轮，注释和实现基本一致，但细节（比如某个参数是「每人」还是「全服」）极易误判
2. **每次改动后立刻验证**：`node --check` → 本地跑 → 线上 curl → 页面确认，四步都不能省
3. **改 payload 记得两处**：`marketPayload`（首屏）+ `tickPayload`（增量）
4. **改前端记得 bump SW**
5. **改数据前先备份**
6. **提交信息写清楚「改了什么 + 为什么」**，方便回溯（本项目一个功能往往要改 4~6 个文件）
