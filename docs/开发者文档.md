## 1. 项目概览

一个 QQ 群风格的**模拟炒股网页游戏**：玩家做多/做空、挂限价单、打工赚钱、买主题皮肤、互相偷钱、抢指数涨跌。

| 项 | 值 |
|---|---|
| 语言/运行时 | Node.js（ES Module，**零第三方依赖**） |
| 服务端 | `node:http` 手写路由 + SSE 推送 |
| 前端 | 原生 HTML/CSS/JS，**无构建步骤** |
| 存储 | 单个 `data/db.json`，防抖写入 |
| 时间粒度 | `tickMs = 5000`（1 轮 = 5 秒） |
| 部署 | 腾讯云 47.103.83.218，`/opt/xdstock`，systemd 服务 `xdstock` |

**设计底线**：不引入任何 npm 依赖、不引入打包器。所有功能用标准库 + 原生浏览器 API 实现。

## 5. 每轮 tick 的流水线（`src/engine.js#stepMarket`）

顺序**不能随意调整**，会影响结算正确性：

```
1. 新闻推进（阶段切换、到期清理）
2. 券商活跃度中枢 EMA、汇率 EMA
3. 每只票走一步 stepStock()
     噪声 → 新闻冲击 → 漂移 → 特质修正 → 均值回归 → 散户情绪 → 玩家冲击 → 价格钳制
4. genMarketTrades()      生成噪声成交
5. 哈基蜂业天气抽奖（低概率暴力拉升/砸盘 + 公告）
6. 汇率向目标价靠拢
7. 指数：成分股价格 → 加权 → 求 DENG 值
8. 小灯指数：同上，取市值最小 7 家 → DENGS
9. rebalanceIndex()       到点调仓（DENG 与 DENGS 同步节奏）
10. runReports()          到点发财报（兄弟股同轮发）
11. 每只票指数标的同步：db.stocks.DENG / DENGS 的 price 与 series 跟随指数
```

`processOrders()`（撮合）由 `server.js` 的 tick 定时器在 `stepMarket` 之后调用。

## 6. 核心子系统

### 6.1 股价引擎（`stepStock`）

对数收益率可加模型：

```js
logRet += 噪声(vol) + 新闻冲击 + 漂移 + 特质修正 + 均值回归 + 散户情绪 + 玩家冲击
price  = price * exp(logRet)
```

- **均值回归**：`logRet += k * ln(fair / price)`，`k = cfg.meanReversion * trait.revMult`
- **散户情绪**：每 `sentRollTicks`(720) 重掷 `v ∈ [-1,1]`；每 `sentTicks`(12) 施加 `v * strength * rand(-1,1)`
- **玩家冲击**：`impact = flow * playerImpactStrength * factor`，封顶 `playerImpactMax`；
  `factor = (impactRefFreeCap / freeCap)^0.6`，大盘股被削弱、小盘股被放大
- **钳制**：单轮涨跌幅限制、ST 阈值触发出局

### 6.2 财报与估值（`src/fundamentals.js`）

- 每 `reportIntervalTicks`(720) 发一期
- `fair = max(EPS × 行业PE × (1+成长溢价), BPS × 0.8)`，平滑 70/30
- 规模衰减：`decay = 1 / (1 + (multiple - 1) * 1.5)`，防止财报数值指数爆炸
- 联动：天气（哈基蜂业）、汇率（留美外汇）、券商成交活跃度（小灯证券）
- **金融大鳄预览**：发布前 20 轮把结果写进 `st.pendingReport`，只有 `theme === 'tycoon'` 的玩家能在 payload 里看到 `preview`；发布时直接用 `pendingReport`，保证所见即所得

### 6.3 指数

| | DENG（灯证指数） | DENGS（小灯指数） |
|---|---|---|
| 成分 | 全部 10 只非指数股 | 市值最小 7 只 |
| 权重 | 流通市值 | 流通市值 |
| 调仓 | 每 2160 轮（3 小时） | **跟随 DENG 的调仓轮次** |

调仓判定必须用 `db.tick === idx.rebalanceTick`（**不是 `>=`**，否则每轮都调仓、指数锁死）。

### 6.4 交易与挂单（`trading.js` / `orders.js`）

- 只支持**限价单**，无市价单
- 每轮每只票**只成交一张单**，其余排队（`filledCodes` Set）
- 单笔每轮成交金额上限 `maxFillNotionalPerTick`（按金额不按股数，避免杠杆套利）
- 下单当轮不成交（`db.tick <= order.createdTick` 直接 skip）
- 每人每轮操作次数上限 `maxOrdersPerTick`（**只限个人，全服无限制**）
- 每人同时挂单上限 `maxPendingOrders`

**前端让利**：`public/app.js` 的 `getSlipPct()` 读 `localStorage.xd_slip`（默认 0.5%），决定自动挂单价比现价让多少。

### 6.5 止盈止损

- 每个持仓可有**多条**分段条件单：`pos.tpsl = [{ id, kind: 'tp'|'sl', price, qty }]`
- 每条可独立设数量（部分平仓）
- 触发后标记 `fired`，不再重复触发

### 6.6 主题技能

| 主题 | 技能 | 实现位置 |
|---|---|---|
| 🐂 红红的牛 | 指数多头排列时平仓返 1% 成交额 | `trading.js#closePosition` |
| 🐻 绿绿的熊 | 指数空头排列时平仓返 1% | 同上 |
| 🐊 金融大鳄 | 提前 20 轮预览金融板块财报 | `api.js` payload + `engine.js` |
| 🕶️ 暗黑大手 | 成交对市场冲击额外 +5% | `trading.js#addFlow` 调用处 |
| 🧙 隐世仙人 | 成交有 50% 概率不出现在别人的成交记录里 | `api.js#/api/stock-trades`（按单号哈希，保证稳定不闪） |

红牛/绿熊返现是**每笔平仓独立判定**，用 `redBonusMinTicks` 防止开平刷奖励。

### 6.7 账号等级与分级商店

- `player.level` 默认 1
- 升级门槛：`levelBaseAsset * levelGrowth^(level-1)`（默认 1000万 ×2 → 1000万/2000万/4000万…）
- 升级费用：**当前总资产 × `levelUpRatio`（60%）**，按点击那一刻重算
- 商店分 Lv.1 / Lv.2 / Lv.3 三档，`data-tier` 标记，等级不足只显示锁定提示
- Lv.2 商品：自定义背景（500 万买断，图片存 dataURL）、改名卡（100 万，2000 轮冷却）

### 6.8 噪声成交（`marketTrades.js`）

每轮编 `rand(1,2) × marketTradesRate` 笔散户成交，写进 `db.trades`（`isMarket: true`），**不推动价格**，只为让成交列表有生气。指数标的也算在内。

## 7. 配置系统（三层，务必分清）

```
src/config.js DEFAULT_CONFIG   ← 代码默认值（改这里影响新存档）
        ↓ 启动合并
data/db.json  config           ← 线上实际生效值（管理面板改的就是这里）
        ↓
/api/market 返回 config        ← 前端读到的
```

**新增一个可调参数的标准动作（四处都要改，漏一处就会出现「面板上有但改了没用」）：**

1. `src/config.js`：加默认值 + 注释
2. `src/api.js`：管理员白名单数组里加 key（约 L760~780）
3. `src/api.js`：`marketPayload` 的 `config` 对象里下发
4. `public/app.js`：管理面板 `PARAM_GROUPS`（或同类数组）里加 `['key', '中文标签']`

改完还要在线上 `db.json` 里写入实际值（否则用默认）：

```python
d['config']['新参数'] = 值
```

## 8. 前后端通信

### REST

- 全部在 `src/api.js`，路由用 `if (pathname === '...')` 平铺
- 鉴权：`Authorization: Bearer <token>`，`auth(ctx)` 解析出玩家
- 管理接口在 `/api/admin/*`，用 `adminPin` 换取 admin token
- 返回统一 `json(res, status, obj)`

### SSE（`/api/stream`）

- 每轮 tick 向所有连接推送 `tickPayload(forPlayerId)`
- 载荷含：`tick`、`stocks`（价格/涨跌幅）、`me`（持仓/现金/订单/等级）、`events`、`notices`、`index`、`indexWeights`、`smallIndex`、`preview`、`tpsl`

> ⚠️ **新增字段必须同时加到 `marketPayload`（首屏快照）和 `tickPayload`（增量推送）**。
> 只加一处会出现「刷新才有、平时不更新」或反过来。这是本项目最高频的 bug 来源。

### 前端状态

```js
state = {
  market, me, code, tf, tradeTab, shopTier,
  market: { stocks, index, smallIndex, config, events, notices, me }
}
```

所有渲染函数形如 `renderXxx()`，读 `state.market` 重绘。**不要在前端缓存业务状态**，一律以服务端 payload 为准。

## 12. 已知坑（血泪清单，动手前必读）

### 12.1 编辑文件

- **中文内容一律用 `write` 工具，或用 Python 以 `newline='\n'` 写入**
- **不要在 PowerShell 里内联 Python 传中文/引号**（会被解析成命令，报一堆 “无法识别” 错误）→ 先写临时 `.py` 文件再执行，跑完删除
- **不要用花括号配对来删函数/代码块**——之前删划线功能时用正则匹配括号，误删了 `placeLimit` 等函数导致整页崩溃
  正确做法：按行号定位 → 只删目标区间 → 删完 grep 一遍关键函数名确认还在 → `node --check`

### 12.2 前端

- **`hidden` class 会被 `.shop-grid { display: grid }` 覆盖**（特异性相同，后者更靠后）→ 切显隐时用 `el.style.display = 'none'/''` 兜底
- **DOM 嵌套错误会静默失效**：父元素被 `display:none` 时，子元素无论怎么设置都看不见。改完 HTML 结构要数 `<div>` 和 `</div>` 是否配平
- **改静态资源必须 bump `sw.js` 的 CACHE**，否则用户看到的还是旧文件（典型症状：「改了没生效」）

### 12.3 服务端

- **兄弟股同轮发报**：`sib.nextReportTick` 必须设成 `db.tick`（当前值），不能赋 `st.nextReportTick`（旧值）——否则会每 tick 都发报
- **小灯指数调仓**：判定用 `db.tick === idx.rebalanceTick`，不能用 `>=`（会每轮触发，指数锁死）
- **指数标的（DENG/DENGS）不走 `stepStock`**，所以它们的 `series` 要在指数计算处手动 push，否则涨跌幅恒为 0
- **`0` 与 `undefined`**：`Number(cfg.x) || fallback` 会把合法的 0 吞掉，用 `??` 或显式判断

### 12.4 个股面板

个股参数只在 `public/app.js` 的 **`TRAIT_LABELS` 白名单**里出现的 key 才会渲染。新增个股级参数时：
1. 在 `TRAIT_LABELS` 加 `key: ['中文名', '提示']`
2. 在 `store.js#migrate` 给每只票补默认值（否则老票没有这个字段，面板不显示）

## 14. 最近的关键修复（了解历史，避免重蹈覆辙）

| 问题 | 根因 | 修复 |
|---|---|---|
| 农业股每 tick 发报 | 兄弟股同步用了旧 tick | 改成 `db.tick` |

## 16. 给下一位维护者的建议

1. **改之前先读代码，不要凭记忆改**——这个项目迭代了很多轮，注释和实现基本一致，但细节（比如某个参数是「每人」还是「全服」）极易误判
2. **每次改动后立刻验证**：`node --check` → 本地跑 → 线上 curl → 页面确认，四步都不能省
3. **改 payload 记得两处**：`marketPayload`（首屏）+ `tickPayload`（增量）
4. **改前端记得 bump SW**
5. **改数据前先备份**
6. **提交信息写清楚「改了什么 + 为什么」**，方便回溯（本项目一个功能往往要改 4~6 个文件）
